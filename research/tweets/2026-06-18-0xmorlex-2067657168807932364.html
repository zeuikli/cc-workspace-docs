CLAUDE.md 哲學：「等待需求」（Wait for Demand）

  • Boris 個人的 CLAUDE.md 只有兩行：
    1. 每次開 PR 自動 enable auto merge
    2. 每次開 PR 貼到團隊 Slack channel 求 stamp

  • 核心原則：不事先設計 UI，因為六個月後模型已完全不同，所有 scaffolding 都會過時

不要為模型加 scaffolding

  • 要麼：每次模型更新後重建 → 要麼：等下一個模型，免費得到那 20%

Part 2：AI Second Brain — 五個層次架構 ​

另一創作者的 Claude Code 知識管理教學，用 Markdown 檔案組織個人/團隊知識庫。

核心理念

  • 「你的模型就是你的資料，你的 IP」
  • 問題不是有沒有資料，而是 agent 能不能在對的地方找到它

五個層次

層次特徵適用情境
Level 1手動資料夾結構，靠精確關鍵字搜尋入門，<30 個筆記
Level 2LLM Wiki，帶關係圖（Obsidian 視覺化）30+ 筆記，需要概念關聯
Level 3語意搜尋，不靠精確字詞路由失效，需要模糊查詢
Level 4知識圖譜，追蹤問題鏈複雜關係推理
Level 5多 Agent 離線同步（如 G-brain）大型團隊資料同步

關鍵設計原則

  • 反向工程：先想「未來怎麼用這個資料」再決定怎麼存
  • 「籃球框和籃球」：知道資料怎麼被取用，才能決定存放格式
  • 整個專案不需要只在一個層次：某資料夾 Level 2，另一個 Level 4 完全合理

工具提及

  • Obsidian（視覺化 Markdown 關係）
  • GitIngest（GitHub repo → 單一文字）
  • DeepWiki（自動為 repo 生成 docs）
  • Hermes agent、Codex（second brain 與多模型兼容）
