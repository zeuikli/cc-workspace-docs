核心摘要 ​

Boris Cherny（Claude Code 負責人）於 Meta 舉辦的開發者活動中接受 fireside chat，分享 Claude Code 現況、Fable 模型突破、Loops 典範轉移，以及 Auto Mode 安全機制。

主要論點 ​

Loops 是下一個大躍進

  • Boris 核心主張：Loops（agent 循環運行）與「source code → agents」一樣重要，甚至更大
  • 他個人已有 agent 全天候在 loop 中處理所有任務（如：自動訂機票、飯店）
  • co-work agent 範例：每天掃 email + Google Calendar，自動完成跨城市差旅訂票，Boris 完全不需介入

Claude Code 現況（截至 2026 年初）

  • 自 Opus 4.5（2025 年 11 月）起，Boris 就已完全用 Claude Code 寫所有程式，並卸載 IDE
  • Anthropic 內部 80–90% 程式碼由 Claude Code 撰寫；Cloud Code 本身、co-work = 100% AI 生成
  • 2026 年 Anthropic 工程師人均程式碼產出成長 8 倍
  • 1,700 PR、新增 400,000 行、刪除 250,000 行（Boris 個人年度數字）

Fable 的重要性

  • Boris：Opus 4.8 → Fable 的飛躍 ≥ 前一次 Opus 4.5 大躍進，可能更大
  • Fable 特點：能理解細微差異、像最聰明同事一樣思考、偵錯時會形成假設追蹤證據
  • Boris 直言「已找不到能難倒 Fable 的問題」，幾乎每題一次解決
  • Fable 目前受到限制，Boris 稱是「誤解」，正在推動恢復

ROI 思維 vs. 成本控制

  • 正確框架：專注提升 return，而非削減 token 成本
  • 部署建議：給全公司（含 PM、設計師、財務）都發 token，讓創新自然浮現
  • 100% AI 寫程式後，新瓶頸 = 好創意 → 需要更多 PM、UX 研究員、快速上市能力

Auto Mode 與安全

  • 傳統「人在迴路」的 yes/no 許可提示 → 人會習慣性按 yes，反而降低安全性
  • Auto Mode：每個許可請求由模型依對話上下文自動判斷，比人工判斷更安全
  • Anthropic 模型在 100 次嘗試中 prompt injection 成功率 ≈ 1%，業界最低
  • 搭配 prompt injection classifier → 模型幾乎免疫此類攻擊
  • Auto Mode 解鎖長時間 agent 運行（數小時甚至數天）

Output Styles（學習模式）

  • exploratory：Claude 解釋架構/語言/程式碼再修改，幫助工程師邊做邊學
  • learning：只教怎麼做，不代為執行，適合新語言練習

協作功能

  • 現階段 Claude Code 較偏單人工具，GitHub 整合為「湊合用」
  • Boris 承認協作體驗需改善，但具體路線圖未透露
