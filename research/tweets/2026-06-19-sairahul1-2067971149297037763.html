Andrej Karpathy 對學生（學士/碩士/博士）演講：「軟體在 AI 時代」完整版。用 Software 1.0/2.0/3.0 三代框架解析 LLM 本質，並指出 90% AI 建議的半衰期僅 6 個月——現在最重要的是理解 LLM 底層心理學，才能在快速迭代中保持競爭力。

Software 三代框架 ​

Software 1.0 — 傳統程式碼

  • 明確指令給電腦（Python、C++ 等）
  • 70 年來基本未變

Software 2.0 — 神經網路權重

  • 你不直接撰寫，而是訓練出來
  • Tesla Autopilot 例子：隨著 NN 擴大，大量 C++ 程式碼被刪除並遷移進 2.0
  • HuggingFace ≈ GitHub 之於 Software 2.0

Software 3.0 — LLM prompts（用英文程式設計）

  • LLM 成為「可程式化的神經網路」，prompt 就是程式
  • 這是 Karpathy 最著名觀點：我們正在用英文寫程式

LLM 的本質：複雜的作業系統 ​

  • LLM ≈ 1960 年代的電腦，現在正在重做計算歷史
  • 透過「time-sharing」（API / ChatGPT）提供服務，就像早期大型機
  • 前所未有之處：這次是直接給大眾，而非先給政府/大企業
    • 歷史規律：電力、密碼學、GPS → 先政府，後消費者
    • LLM 顛倒了這個方向：先到普通人手中

LLM 的心理學（關鍵認知） ​

超能力

  • 百科全書式記憶（Rain Man 類比）
  • 跨領域知識整合

認知缺陷

  • 幻覺（hallucination）
  • 參差不齊的智能（9.11 > 9.9、strawberry 有幾個 R）
  • 順行性遺忘症（Memento / 50 First Dates 類比）：context window 就是工作記憶，每次清空，不會自動累積知識

如何有效使用 LLM ​

1. 讓 LLM 可讀取你的資料

  • 文件要改為 LLM 友好格式：把 "click here" 改成對應 curl 指令
  • 工具：GitIngest（把 GitHub repo 轉成單一大文字）、DeepWiki（自動為 repo 建 docs）

2. MCP（Model Context Protocol）

  • Anthropic 提出的協定，讓 agent 可直接與工具溝通
  • Karpathy 看好：為 LLM 作為新型「數位資訊消費者」鋪路

3. 快速 iteration loop

  • 現在可以極快速地測試、部署、迭代 LLM 應用
  • 未來 10 年：人機協作的「滑桿」將從左（人主導）移到右（AI 主導）
