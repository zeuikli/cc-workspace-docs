# MCP 2026-07-28 規格更新與 Claude 支援

> 整理日期：2026-08-04
> 基礎：`14-mcp.md`（transport / scope / OAuth / Tool Search 完整指南）——本檔只記本次規格增量。

---

## 這版改了什麼（MCP 第五個規格版本）

| # | 變更 | 意義 |
|---|------|------|
| 1 | **Stateless core** | 從雙向有狀態協定改為 request/response 模型；server 可直接部署在 serverless / edge，擴展與部署大幅簡化 |
| 2 | **Extensions 框架標準化** | MCP Apps 與 Tasks 以**版本化 extension** 出貨，新增能力不必動核心協定 |
| 3 | **Authorization 對齊 OAuth 2.0 / OIDC** | 可直接接 Entra、Okta 等既有 IdP，不再需要 workaround |
| 4 | **MCP Apps（互動 UI）** | server 可在對話中直接算繪互動元件，免切分頁 |
| 5 | **Tasks** | 長時間執行工作的標準化表達 |
| 6 | **企業託管存取** | 管理員透過 IdP 佈建 connector，群組繼承存取權，終端使用者零設定 |

**Claude 端**：Claude 產品線已支援上述能力，可用 MCP server 超過 950 個；已發布的 connector 取得 dashboard，可看效能、採用、錯誤與跨產品使用量。

---

## Claude Code 端的相關行為（同期 changelog）

- MCP 工具呼叫超過 **2 分鐘自動轉背景**，session 保持可用（`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` 可調，v2.1.212）
- MCP 重新認證不再先撤銷可用憑證再登入（v2.1.216）
- 修正 `--mcp-config` 的 server 在 print 模式（`-p`）首輪前未連上，導致模型把工具呼叫吐成純文字（v2.1.213）
- 修正 OAuth MCP server 在 token refresh 後仍要求重新授權（v2.1.206）、per-server `request_timeout_ms` 被忽略（v2.1.206）
- session 工作目錄會出現在 MCP `roots/list`（v2.1.203）

---

## 對本 workspace 的影響

- **Deferred tool loading 紀律不變**：未取 schema 前不可呼叫（`context-management.md`）。stateless core 不改變這點，但讓自建 server 更容易部署。
- 自建 MCP server 若原本依賴長連線的雙向通知，需檢視是否要遷移到 Tasks extension。
- 互動式驗證的 MCP server（如 claude.ai connector）在 headless / cron 執行中可能不可用——`Workflow` 的既有 caveat 依舊成立。
