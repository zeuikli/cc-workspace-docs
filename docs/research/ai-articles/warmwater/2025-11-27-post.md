# 打造台股交易模擬訓練平台：從構想到實作的技術分享

**Date:** 2025-11-27

**Key Technologies:** FastAPI、React、yfinance、Tavily API、SQLite

You've probably wondered: what if you could "travel back in time" to practice stock trading? I built a Taiwan stock trading simulator that lets you replay historical data while viewing real news from that period.

## 為什麼要做這個專案？

Trading's hardest challenge isn't technical analysis—it's **decision-making psychology**. Real money makes people hesitant, yet simulations lack authenticity. This platform's core concept is:

> "Recreate authentic trading scenarios using historical data, letting you practice decision-making risk-free"

Features include:
- 📊 Day-by-day historical K-line playback
- 📰 View actual news from that date (Commercial Times)
- 💰 Simulate trades and track P&L
- 🔍 Search stocks (Chinese names and codes supported)

## 核心功能設計

### 1. Historical Playback Mechanism

Unlike traditional backtesting systems showing complete charts, I designed a "time machine" mode:

- **Daily playback**: Progress day-by-day like video playback
- **Visual masking**: Show only pre-current date data, preventing "future information leaks"
- **Playback controls**: Pause, adjust speed, jump to specific dates

This design makes users **genuinely feel like they're deciding in real-time**, not with hindsight.

### 2. News Integration: Most Important Feature

Price movements have reasons. I integrated **Tavily API** to fetch Commercial Times historical news.

**Technical highlights:**

- **Smart query optimization**: Auto-fetch Chinese company names from Yahoo Finance for precision
  - Example: `8033.TW` → search "8033 雷虎" instead of just "8033"
  - Dramatically improves news relevance
- **URL date parsing**: Commercial Times URLs contain dates (`/YYYYMMDD` format)
  - Solves Tavily's lack of `published_date` for Taiwan news
  - Precisely matches historical news to trading dates
- **Intelligent caching**:
  - First query 1 month → cache to database
  - Query 3 months → auto-fill missing 2 months
  - Uses SQLite for news caching
  - Supports partial cache filling, fetches only missing date ranges
  - Dramatically reduces API calls and wait times

**Why Commercial Times?**

After testing multiple sources, Commercial Times proved most reliable:
- Unified URL format, easy date parsing
- High-quality financial news
- Broad Taiwan stock coverage

### 3. Stock Search: Chinese-Friendly Design

Taiwanese typically discuss stocks by company name, not just codes. I implemented **bidirectional search**:

**Technical architecture:**

- **Pre-built database**:
  - Fetches complete stock lists from TWSE and TPEx
  - Auto-scrapes Chinese names for each stock
  - Stores as JSON file (200+ stocks)
- **Caching mechanism**:
  - Loads to memory on startup, builds name indexes
  - Supports fuzzy search (substring matching)
  - Real-time queries only for unfound stocks
- **Search logic**:
  - Input "2330" → search code → return "2330.TW - 台積電"
  - Input "台積電" → search Chinese name → return "2330.TW - 台積電"
  - Input "雷虎" → search Chinese name → return "8033.TW - 雷虎"

**User experience:**
- Real-time candidate display while typing
- 300ms debounce prevents frequent queries
- Keyboard support (arrow keys, Enter confirmation)

## 技術挑戰與解決方案

### Challenge 1: Weekend News?

**Problem**: Stock markets close weekends, but news publishes. Should Monday playback show weekend news?

**Solution:**
- Designed "trading day reference table" API returning news date ranges per trading day
- Weekend news maps to next trading day
- Example: Saturday/Sunday news displays Monday

### Challenge 2: News Loading Too Slow

**Problem**: 3-month news queries took minutes, poor UX.

**Solution:**

1. **Progressive feedback**:
   - Display percentage progress (0% → 100%)
   - Show current status ("搜尋 2024-08-01 ~ 2024-08-31")

2. **Smart caching strategy**:
   - First query: complete fetch and cache
   - Subsequent queries: check existing ranges, fill gaps only
   - Reduced time from minutes to seconds

3. **Backend logging optimization**:
   ```
   [fetch_and_cache_news] Cache status: 32 cached / 61 missing / 93 total days
   [fetch_and_cache_news] Need to fetch 2 missing ranges
   ```
   - Aids debugging and cache efficiency visibility

### Challenge 3: CORS and Environment Config

**Problem**: Separated frontend/backend, CORS settings and API key management prone to errors.

**Solution:**
- **Unified Makefile**: One-command startup (`make run`)
- **Simplified environment variables**: 8 essential configs only, removed redundancy
- **Auto CORS configuration**: Dev environment auto-allows `localhost:5173`
- **Clear README**: Non-technical users can easily launch

## 前端設計：Cyber 風格的考量

**Cyber aesthetic** creates a "time hack" atmosphere:

- **Monochrome palette**: Cyan-dominant reduces eye strain during long sessions
- **Monospaced fonts**: Numbers clear and readable, like real trading terminals
- **Blurred backgrounds**: Backdrop blur enhances visual hierarchy
- **Smooth animations**: Natural transitions, not overwrought

**Function trumps form**—every visual element serves purpose.

## 開發心得

### 1. Build MVP First

Started with basic price playback, confirmed core functionality before adding news integration. This avoided overengineering, focused on what truly mattered.

### 2. Caching is Key

News queries consumed most time. Smart caching dramatically improved UX. **Good cache strategy = better user experience**.

### 3. Logging Matters

Detailed backend logging (cache status, query ranges, errors) improved debugging 10x. Don't skip logging—future you will thank present you.

### 4. Documentation Beats Memory

Detailed README and `.env.example` mean returning months later requires only 5 minutes. Good documentation is the best gift to your future self.

## 快速開始

Three steps to start:

```bash
# 1. Install dependencies
make install

# 2. Configure Tavily API Key (optional)
cd backend
cp .env.example .env
# Edit .env with your API Key

# 3. Launch
make run
```

Open [http://localhost:5173](http://localhost:5173) to start trading!

Happy trading! 📈
