## 全文摘要

**定位**：Fable = leader（指揮），Opus/Codex/Sonnet = workers（執行）。

### Fable 5 五項能力
1. Never loses the thread（18,000 行代碼遷移 3 小時無人監督完成）
2. Sees like a person（最高 computer-use 分數，可從截圖重建頁面）
3. Delivers finished work, not answers（raw files → deliverable）
4. Gets smarter from files（notes 文件夾 = 跨 run 記憶複利）
5. Built to lead（管理 agent team）

### 三個 Secret
- **Secret 1：Don't overguide**：逐步指令和長規則列表對舊模型是脚手架，對 Fable 是天花板
- **Secret 2：Keep CLAUDE.md light**：只包含「它是什麼/關鍵命令/已知錯誤」
- **Secret 3：Abuse loops and goals**：`/goal` + 小型 judge model 每輪驗收 → 自主工作到完成

### Workers 設定
每個 worker = `.claude/agents/` 裡一個小文件（name / model / short job description）

### 五個高價值 Workflow
1. Giant codebase job（大型遷移，分段+每段獨立 reviewer）
2. Deep research sprints（parallel workers + checker 攻擊每個 claim）
3. Orchestrator（未詳述）
4. Frontend（未詳述）
5. Knowledge base（未詳述）

### 一次完整 Project 流程（Landing Page 示例）
1. Brief → 2. Plan（Shift+Tab plan mode + Pocock skills）→ 3. Team 工作（Fable dispatch worker → verifier 冷驗） → 4. /goal 設置 → 5. 早上 review 帶 proof 的 run log

**Pocock skills**：`github.com/mattpocock/skills`（含 planning skills）

### 整體配置一覽
```
run Fable as leader: pocock skills for plan, Opus/Codex workers for labor, Fable reviews everything
don't overguide: outcome + constraints + reason, delete scaffolding
keep CLAUDE.md light: what it is, commands, known mistakes
abuse goals and loops: finish lines with pasted proof and a written brake
five workflows: codebase / research / orchestrator / frontend / knowledge base
```
