## 研究摘要

**TL;DR**：Opus 4.8 Dynamic Workflows 的關鍵是從「命令式 prompt」升級為「宣告式 completion state」（Don't stop until...），搭配平行 subagent + 對抗性驗證，提供 20 個可直接套用的 workflow prompt 模板。

### 核心論點

1. **範式轉移**：從「寫 10 個廣告想法」→「找出最佳廣告想法後才停下」，是 prompt 到 completion state 的根本升級
2. **Dynamic Workflows 機制**：Claude 自動撰寫 orchestration script，啟動數百個平行 subagent，互相對抗性驗證，只回傳完成品
3. **觸發方式**：Claude Code v2.1.154+、Max/Team/Enterprise plan、`/permissions` auto mode 或 `/effort ultracode`
4. **"Don't stop until" 語法**：是讓 Dynamic Workflows 自動運行的核心 termination condition
5. **20 個實戰模板**：分 4 類（賺錢/行銷成長/內容/研究策略），每個都含具體完成條件

### 關鍵數據 / 工具

- **Opus 4.8 效能**：69.2% SWE-bench Pro（vs 4.7 的 64.3%）、4x 更少遺漏錯誤
- **Fast mode**：2.5x 速度，3x 便宜
- **定價**：$5/$25 per million tokens（input/output）；Max plan $100/month
- **Bun rewrite 案例**：750,000 行 Rust，99.8% test pass，11 天（Jarred Sumner）
- **觸發關鍵字**：prompt 中輸入 "workflow"，或 `/effort ultracode`
- **20 個完整 completion state prompt**（lead gen / cold email / competitor intel / SEO / UGC / due diligence 等）

### 批判性觀察

1. **Dynamic Workflows 描述有行銷誇大成分**：「數百個平行 subagent 互相對抗」聽起來很強，但 Anthropic 官方文件描述較保守；Bun 案例是真實的，但屬極端工程案例，不代表一般 workflow 的效果
2. **部分 workflow 存在操作限制**：Google Maps scraping（服務條款限制）、5000 App Store 評論分析（需 API 或爬蟲）等在 Claude Code 沙盒環境中有實際執行門檻，非一個 prompt 就能完成
3. **completion state 框架本身有價值**：從命令式到宣告式是真實的 LLM 使用升級，"Don't stop until" 語法可立即套用；但要區分「有幫助的框架」與「夜賺萬元的行銷聲明」
