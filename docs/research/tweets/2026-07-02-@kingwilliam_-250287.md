## 全文（核心要點）

**核心重新定位**：Fable = 管理 team 的 lead，不再是聊天機器人。

**11 條核心規則**：

1. Fable 是 manager，不是 chatbot（可管理 50+ subagents）
2. Effort 對齊任務：low/medium = 簡單問答；high = 日常工作（默認）；xhigh = 最難問題；ultracode = 完全自主
3. 給 why，不只給 what（Fable 需要意圖連接上下文）
4. 保持 prompt 短（過度工程化反而降低輸出質量）
5. 四要素結構：Context / Request / Output format / Constraints
6. 設置 Checkpoint（暫停條件：只在花錢/發送外部內容/需要人決策時）
7. Loop 工程：`/goal` 跑到完成；`/loop` 定時循環
8. **Barbell strategy**（= 10-80-10）：Fable 計劃（10%）→ 便宜模型執行（80%）→ Fable 驗證（10%）
9. 建立 Context 系統（4步：`/claude-context/` 文件夾 + `claude-memory.md` 自更新 + `claude-instructions.md` + `/add` 連接）
10. 把重複工作轉為 Skills（三種建法：從過去聊天提取/從頭構建/從數據訓練）
11. 注意事項：舊 prompt 會讓 Fable 更差；早停時說「go ahead and do it end-to-end」

**Checkpoint prompt**：
```
Run this end-to-end on your own and take as long as you need.
Pause for me only when it genuinely matters: spending money, sending
something external, or a call only I can make.
Otherwise don't stop, and show me the finished work when it's done.
```

**Memory 四步**：
```
Step 1: /claude-context/ 文件夾（who/SOPs/client docs/decisions log）
Step 2: claude-memory.md + 規則「Every time I give you major context, update claude-memory.md.」
Step 3: claude-instructions.md（standing brief）
Step 4: /add 或 CLAUDE.md 指向文件夾
```

## 研究摘要

**TL;DR**：Fable 5 Anthropic 官方 playbook 解碼：11 條規則涵蓋 Effort 選擇/四要素結構/Barbell strategy/Loop/Memory 四步建設/Skills 三種建法。

### 核心論點

- Fable 是 manager 角色轉變，停止微觀管理，開始目標委派
- 短 prompt 優於長 prompt（反直覺）
- Barbell strategy = 10-80-10（與 milesdeutscher 相同框架，不同命名）
- Memory 系統四步可立即實施

### 關鍵數據 / 工具

- Effort 五段：low/medium/high/xhigh/ultracode
- `/goal` / `/loop` / `/loop stop [name]`
- Memory path：`/claude-context/` + `claude-memory.md`

### 批判性觀察

- 與 wquguru、milesdeutscher 重疊度高（四要素、10-80-10、Loop）
- 「Anthropic's playbook, decoded」說法誇大，無具體 Anthropic 文件引用
- Memory 四步的 self-update 機制（claude-memory.md 自動更新規則）是有價值的具體實踐
