## What I found

My most expensive sessions weren't the complex ones.
They were long sessions where I kept adding more without clearing out and simple PRs I was going back and forth on without a stopping condition.
Most of the waste wasn't the model being inefficient. The constraint turned out to be useful. More precise questions get better answers.

Here are the 11 things I implemented.

[圖 3]

## What I implemented

1. Clean up your CLAUDE.md

Open your CLAUDE.md and cut anything Claude would do anyway. Every line loads on every single request. Keep it under 200 lines.

Replace long paragraphs with short rules:

```bash
- Reply concisely. No filler. No "Great question!"
- Code only unless I ask for explanation.
- Never repeat my question back to me.
- When done, stop. Don't summarize what you just did.
- Use TODO comments instead of explaining inline.
```

2. Switch models with /models

Type /model mid-session to switch without restarting.
Most people pick one model and leave it. That's wasteful.
- Opus / Sonnet 4 → complex refactors, architecture, hard bugs
- Sonnet → tests, simple edits, explaining code
- Haiku → quick lookups, formatting, renaming, anything repetitive

I was using Sonnet for everything. Haiku handles most of my daily work and costs a fraction.

3. Write one complete prompt instead of going back and forth

Stop sending:
fix this bug → now refactor it → ok add tests

Write it once:
"Fix the bug, refactor, and add tests."

Every follow-up forces a full re-read from the top. One prompt reads context once and produces one solution.

4. Use /compact before switching tasks

/compact summarizes your session and resets it while keeping intent.
Run it before every task switch, not just when things feel slow.

You can guide what it keeps:
/compact focus on the backend changes

[圖 4 — 來源: summarizing with /compact]

/clear when you're done with a topic entirely.
And when you're done for the day: leave a quick note on what is the session id you have left.

When you come back, run claude --resume `<session-id>`, Claude shows the session ID right after you exit.
You pick up exactly where you were, no re-indexing, no re-explaining the codebase.

[圖 5 — 來源: note the resume from Claude Code]

5. Add a one-liner to your system prompt

Respond like you're sending a Slack message, not writing a blog post.

Or more direct:
Ultra-concise mode: fewest possible words. Fragments ok.

40-60% fewer output tokens on reasoning tasks.

(There's a whole Reddit thread where people pushed this to the extreme, making Claude respond in "dinosaur language" to strip all padding. It works. I'm not going to tell you to do it.)

6. Turn on prompt caching

If you're sending the same system prompt or reference doc on every request, add cache_control: ephemeral to those blocks.
You pay ~10x less on cached tokens.

This was my single biggest cost reduction.

7. Use CLI and skills before reaching for MCP

Priority order:
1. CLI, gh instead of GitHub MCP, aws instead of AWS MCP. Zero overhead.
1. Skills, load on demand, only when invoked
1. MC, only if nothing else works

Run /mcp to see what's active. Disable anything you're not using.

8. Install the Context-mode plugin

If you rely on MCP servers, install Context-mode. It indexes MCP tool output in a sandbox instead of dumping raw JSON into your session. It claims that it can cut MCP token usage by 50-90% and runs in the background, nothing to manage. What I have seen is it cuts my token.

9. Install mem0 as a memory layer

Every session, Claude starts from zero. It re-reads your CLAUDE.md (probably outdated), walks your file tree, opens every relevant file, re-discovering things it already knew last week. You pay for that loop every time.

The difference between typing fix auth vs fix auth in src/auth.js is massive. But your CLAUDE.md won't remember where auth lives after you refactor it. It's static.

mem0 sits between you and Claude. Before Claude starts reading files, it pulls what's already known. Claude skips the discovery phase and goes straight to the work.

The tokens you save aren't from shorter prompts. They're from not paying to re-learn the same codebase every session.

Type this in terminal to install.

```bash
/plugin marketplace add mem0ai/mem0
/plugin install mem0@mem0-plugins
```

> Context-mode vs mem0, quick distinction:
> Context-mode = less noise per session (compresses what MCP tools dump into your context).
> mem0 = no amnesia between sessions (remembers your codebase so Claude doesn't start from zero every time).
> They work well together.

10. Use images instead of describing the problem

Claude Code accepts images, just drag and drop them into the CLI.
A picture is worth a thousand words / tokens. Instead of writing three paragraphs explaining what's broken in your UI, drop a screenshot.

This is especially useful for frontend bugs and layout issues.
Less explaining, faster fixes.
11. Run a local model when you hit the limit

When you run out mid-week, point Claude Code at a local model. Free, no API key needed.

I use LM Studio:
1. Download at lmstudio.ai
1. Search Qwen3-Coder and download model that you prefer.

I am running it on Mac M5 48GB RAM (Apple Silicon): Qwen3-Coder-30B-A3B-Instruct MLX 4bit.
If you are on a computer with 16GB RAM,  you can use Qwen3-Coder-7B

1. Go to Developer tab → Start Server (runs on localhost:1234)
1. Set env vars before launching Claude:

```bash
export ANTHROPIC_BASE_URL=http://localhost:1234/v1
export ANTHROPIC_MODEL=qwen3-coder-30b-a3b-instruct
```

Type claude, it runs locally, no limits.
Good for simpler tasks. Not a full replacement for Sonnet on hard problems.

## 研究摘要

**TL;DR**：11 個免費技巧降低 Claude Code token 消耗，核心是 CLAUDE.md 精簡、模型路由、prompt caching 與 /compact 策略。

### 核心論點

- token 最貴的不是複雜任務，而是反覆往返的長 session 和沒有停止條件的 PR
- CLAUDE.md 每行都在每次請求載入，精簡到 200 行以下是最直接的降耗
- 模型路由：Haiku 日常任務 → Sonnet 中級 → Opus 架構/難題
- prompt caching (`cache_control: ephemeral`) 是最大單項成本削減，cached tokens 費用 ~10x 更低
- mem0 消除跨 session 重新探索成本；Context-mode 壓縮 MCP tool output

### 關鍵數據 / 工具

- CLAUDE.md 上限：200 行
- 壓縮 system prompt 效果：40-60% 減少 output tokens
- Prompt caching 效益：~10x 成本降低
- Context-mode：聲稱削減 50-90% MCP token 用量
- mem0 安裝：`/plugin marketplace add mem0ai/mem0`
- LM Studio fallback：Qwen3-Coder-30B (M5 48GB) 或 Qwen3-Coder-7B (16GB RAM)
- 本地端點：`localhost:1234`，設定 `ANTHROPIC_BASE_URL` 即可切換

### 批判性觀察

- "40-60% output token reduction" 和 "50-90% MCP reduction" 均為作者自測，缺乏可重複基準；Context-mode 段落自相矛盾（引用官方數字後說「what I have seen is it cuts my token」，無具體數據）
- 壓縮 system prompt 策略會影響回應品質，文中完全未討論品質 / 效率 trade-off
- mem0 插件的 session 持久記憶訴求尚待驗證；CLAUDE.md 不更新問題可能比記憶層更根本
