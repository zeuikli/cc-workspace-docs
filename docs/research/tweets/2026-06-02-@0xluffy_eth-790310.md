## 全文

大多数人还在把 AI Agent 当聊天机器人用。
我连续几个月 24 小时跑 Hermes Agent，测试了安装、模型、任务、Dashboard、多 Agent、记忆、自我改进和安全设置。
看完这篇，你会知道怎么把它变成一个真正能替你干活的 AI 员工。

【先说结论】

Hermes Agent 最恐怖的地方，不是它能执行任务。
而是它会记住你是谁、你做过什么、你怎么工作，并且每完成一次任务，就把经验写进自己的技能库。

ChatGPT 和 Claude 是"每次重新认识你"。
Hermes 是"越用越懂你"。
这就是差距。

【它是谁】

Hermes Agent 是 Nous Research 做的 24/7 自主 AI 员工。
它不是普通聊天框。
你给它目标，它会拆任务、执行、复盘、沉淀经验，下次再做同类任务时，直接沿用之前学到的方法。

它真正强在 3 件事：
1. 记忆存在你电脑里
1. 每次任务后会自我改进
1. 所有历史会话都能被召回

记忆不是黑箱，也不是云端数据库。
它以 markdown 文件存在本地，你可以打开、修改、删除。
所以你不是在"用一个工具"。
你是在训练一个越来越像你助理的人。

【比谁强】

Hermes 更像 Chief of Staff。
Claude Code / Codex 更像深度编程搭子。
OpenClaw 更像早期强，但现在越来越臃肿的 Agent 框架。

Hermes 的优势很明显：更轻、更快、更新不容易炸。
还自带多 Agent Kanban、Nous Portal、166 个技能、20+ 消息平台。

日常任务、研究、文档、运营、内容、电脑管理，用 Hermes。
深度写代码、大型项目、复杂测试，用 Claude Code 或 Codex。
不要混着用。它们不是替代关系，是分工关系。

【怎么安装】

macOS / Linux / WSL2 / Android Termux：
```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh
```

Windows PowerShell：
```bash
iex (irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1)
```

装完直接输入 `hermes`，它会带你选模型、配置消息平台。
如果之前装过 OpenClaw：**不要导入记忆**，重新开始更干净，两个 Agent 独立记忆长期更稳定。

【模型选择】

```
复杂推理 / 长任务 / 商业判断   -> Claude Opus 4 / Sonnet 4（重度使用每月可能几百美元）
新手 / 日常编码 / 原型          -> GPT-5.5（可吃现有 ChatGPT 订阅）
省钱 / 长时间自主任务           -> Qwen 3.7 Max
X 内容研究                      -> Grok
不想管理 API Key                -> Nous Portal
```

随时切换：`hermes model`（不用重装，不用改代码）

【消息平台】

直接用 Telegram。Hermes 支持 20+ 平台，但 Telegram 最适合 Agent：BotFather 配置快、手机体验好、消息稳定。
在 Telegram 创建 Bot，把 token 填进 Hermes，5 分钟结束。
然后你就能在手机上远程指挥你的 AI 员工。

【第一天】

第一条消息发这个：
```
这是我的基本信息：
名字：[你的名字]
我在做：[你的业务/职业]
我现在的项目：[项目列表]
未来 3-6 个月目标：[具体目标]
我的工作习惯：[偏好/时间/格式要求]
我的时区：[你的时区]
```

跳过这步，Hermes 就是在盲干。认真写，它后面所有主动任务都会围绕你的目标过滤。

【定时任务】

Hermes 最像员工的地方是 cron job（定时自动任务）：
```
每天凌晨 2 点，帮我自动做一个小工具、小页面或小系统。
要求是：节省我的时间，推进我的目标，最好能让我第二天早上看到时有惊喜。
```

你睡觉的时候，它真的会继续干活。这才是 Agent 和聊天机器人的分水岭。
**聊天机器人等你问。Agent 主动推进。**

【核心命令】

```bash
/goal [任务描述]    # 启动自主任务
/goal status        # 查看状态
/goal pause         # 暂停
/goal resume        # 继续
/goal clear         # 结束当前目标
/subgoal [补充条件] # 中途追加条件
```

提高 max_turns（研究/报告设 20，代码重构设 50，不要乱设更高，每一轮都烧 token）：
```bash
hermes config set goals.max_turns 20
```

【看板才是核心】

```bash
hermes dashboard    # 进入 localhost:9119
```

**99% 的人第一眼去看模型，错了。先看 Skills 和 Kanban。**

- **Models**：切模型
- **Cron**：定时任务
- **Skills**：它学会了什么
- **Plugins**：浏览器、爬取、电脑控制
- **Profiles**：多 Agent
- **Kanban**：最重要的任务中控台

Kanban 状态流：`Triage -> To-Do -> Ready -> In Progress -> Blocked -> Done`
每天早上把待办写进去，能交给 AI 的全部丢进 Triage，然后走人。

【常用场景（8 个）】

1. **每日学习教练**：丢 YouTube transcript -> 提炼核心概念 -> 每天 8 点提醒 + 测试
2. **文件和电脑管理**：配合 Tailscale，跨设备移动文件，不用 SSH/网盘
3. **历史会话召回**：FTS5 全文搜索 + LLM 总结，找上月讨论过的商业点子
4. **X 内容工作流**：xurl 技能研究 X 讨论 -> 生成 -> 发布（先人工审核 5-7 次再开半自动）
5. **自定义工作台**：Mission Control = 选题池 + 记忆 wiki + 文档库 + 任务状态
6. **原型构建**：gym 里想到产品点子 -> Telegram 发 -> 回家看到 landing page
7. **商业顾问**：结合你的业务/目标/历史偏好给判断，不是通用框架
8. **睡前长任务**：/goal 竞品调研 -> 第二天醒来拿接近人工分析师水平的初稿

【多 Agent 分工】

一个 Profile = 一个独立 Agent（独立记忆/技能/模型/角色）：
```
Chief of Staff  -> 汇总、派活、每天早上发简报
Head of Research -> 找资料、盯竞品、监控 X
Head of Content -> 写内容、改写、拆长文、维护选题库
DevOps Engineer -> 脚本、部署、本地系统、自动化
```

各 Agent 独立成长，由 Chief of Staff 汇总给你。

【真正优势：自我改进】

循环：你给任务 -> 它执行 -> 复盘哪里做对/错/下次怎么更快 -> 经验写入 `~/.hermes/skills/` -> 下次直接调用

区别在于：
- 它的经验可以被你打开
- 它的技能可以被你编辑
- 它的记忆可以被你删除

没有黑箱。

【安全问题】

个人使用安全风险被夸大了。它主要做你明确要求的事。

最低限度的安全规则：
```
# soul.md 写死
Never send money to anyone without explicit confirmation.
```

**不要让它**：自动转账、自动删除重要文件、自动发布高风险内容。

生产环境：Bitwarden Secrets Manager（管真实密钥）+ iron-proxy（给 Agent 代理 token，沙箱里拿不到真正 API Key）。
个人用户：主电脑安装，谨慎授权，危险操作人工确认，够了。

【Hermes 入门框架】

1. 先告诉 Hermes 你是谁
2. 第一周只跑低风险任务
3. Telegram 作为主入口
4. GPT-5.5 起步，复杂任务再上 Claude
5. 每天至少建一个 cron job
6. 用 /goal 跑长任务
7. Dashboard 先看 Skills 和 Kanban
8. Profiles 拆成多个角色
9. 自动发布前先人工审核 5-7 次
10. 在 soul.md 写清楚安全底线

【真实判断】

AI Agent 的瓶颈已经不是模型，而是**记忆、自我改进和信任**。Hermes 正好打中这 3 个点。

第 1 天，它不了解你。
第 30 天，它知道你的项目、风格、常用工具。
第 180 天，它知道你怎么思考、哪些任务每天重复、哪些流程最省时间。

真正的 AI Agent 不是更会聊天，而是能持续积累工作经验。

## 研究摘要

**TL;DR**：作者連幾個月 24h 跑 Hermes Agent 的完整使用指南，核心主張是 Agent 的差異化在「記憶＋自我改進＋信任」三角，而非模型能力，cron job 是 Agent 與聊天機器人的分水嶺。

### 核心論點

1. **Hermes vs. ChatGPT/Claude 根本差異**：後者每次重新認識，Hermes 越用越懂你，任務後經驗寫入 `~/.hermes/skills/`
2. **cron job 是分水嶺**：睡覺時 Agent 繼續工作，定時任務讓它成為真正的員工而非聊天框
3. **Dashboard 正確使用順序**：先看 Skills 和 Kanban，不是模型；Kanban Triage 是任務中控台
4. **多 Agent 分工哲學**：Chief of Staff / Research / Content / DevOps 各自獨立成長，再由 CoS 匯總
5. **安全底線**：soul.md 寫死不自動轉帳/刪除/高風險發布；生產環境加 Bitwarden + iron-proxy

### 關鍵數據 / 工具

- Hermes Agent：Nous Research，localhost:9119，166 內建 skills，20+ 消息平台
- 安裝：curl install.sh（macOS/Linux/WSL2/Android Termux）
- 核心命令：`/goal`、`/subgoal`、`hermes model`、`hermes config set goals.max_turns`
- max_turns 建議：研究/報告 20，代碼重構 50
- 記憶路徑：`~/.hermes/skills/`（markdown，FTS5 全文搜索 + LLM 摘要）
- 安全工具：Bitwarden Secrets Manager + iron-proxy（生產環境）

### 批判性觀察

1. 自我改進機制描述很吸引（「越用越懂你」），但無量化數據，30/180 天差異為作者主觀描述
2. 文章明確說 Hermes 與 Claude Code「不要混著用，是分工關係」—— 對 Claude Code 重度用戶，整合價值有限
3. 模型選擇部分（GPT-5.5 起步）有時效性問題，且與現有 workspace 的 Claude 優先策略衝突
