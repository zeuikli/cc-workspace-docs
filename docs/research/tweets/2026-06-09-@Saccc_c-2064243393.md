## 核心摘要

> Claude Code 創始人 Boris 與團隊成員分享當前工作流程：告別 plan mode 全面轉向 auto mode、用 routines 自動化 CI/bug fix、「與其告訴 Claude 怎麼做不如讓它寫進 skill 永久記住」，以及對未來角色合併（PM＝工程師＝設計師）的判斷。

### 主要洞見

**1. 不再用 Plan Mode，全開 Auto Mode**
- 從 Claude 4.6 起 plan mode 已不必要；新模型不需要顯式規劃步驟
- Auto mode 安全性反而高於人工審核每個 permission prompt（人眼對 99% yes 的請求會麻木）
- 內部收集了數千條 agent trajectory + 紅隊攻擊測試，才確信 auto mode 可信賴

**2. Loop 哲學：與其糾正 Claude，不如讓 Claude 自己記住**
- 每次 Claude 犯錯，不是告訴它「這次別這樣」，而是讓它把修正寫進 `.claude/` skill 或規則
- 這樣 Claude 可以永遠跑下去（the loop runs forever）
- Verification 是關鍵：能讓 agent 執行並檢查自己的結果才是真正的 loop

**3. Routines 是 Agent SDK 最明顯的第一個殺手應用**
- 團隊成員 Niran 設置 routine：監聽 voice mode 所有 GitHub issue → 自動 fix → ping PR
- Boris 自己的 bug 被「另一個 Claude」在 5 小時內自動修完並發 PR
- 不再需要手動回應 code review 留言、修 CI、做 rebase

**4. Context Engineering 已死，給模型最少資訊**
- Sonnet 3.5 時代要 prompt engineering；Opus 4 時代要 context engineering
- 今天的模型：給最精簡的 system prompt + 最少工具，讓模型自己探索
- 過多 context = 在微管理模型，反而限制它找到更好路徑

**5. 角色合併：PM、設計師、工程師界線消失**
- 設計師 Megan 直接發 PR 修按鈕；PM 和財務團隊都在用 Claude Code
- 「所有角色都在合併」——重要的是有產品直覺和 end-to-end ownership 的人
- 比較電腦普及：以前紙本流程放電腦旁，不夠，必須把電腦放中心、丟掉紙本；AI 也一樣

**6. 手機遠端控制代替電腦**
- Boris 把電腦留在辦公室，在家沙發用手機遠端控制、語音模式啟動新 agent
- 「我不需要回辦公室，我在沙發上寫 code，Claude 在電腦上跑」

### Auto Mode 取代 Plan Mode（07:25–10:30）

What they used to be is plan mode. I don't use that anymore. What do you use instead? Auto mode. It's the best. Instead of plan mode? Instead of plan mode. Yeah, because the newer models, they don't actually need like a planning step anymore. I think this was really important for like Opus 4 through maybe 4.5. Then I think starting with 4.6 and definitely with 4.7, it just doesn't need that planning step.

And at the time, that was kind of the best we had a year and a half ago because we didn't have classifiers. The model was not as well aligned as it is today. So auto mode was just such a big step up because actually you don't want to read most of these requests. Just routing it to a different model and having it check for security works so much better.

It's just human nature when you accept 99% of requests that your eyes just glaze over and so actually we feel that auto mode is more safe than reading every single permission prompt because it means that you're only paying attention to the most important thing and not like being spammed a bunch of things that are just 99% yes.

### Auto Mode 安全性紅隊測試（10:05–10:45）

Internally to actually get auto mode out to our users, we needed to really trust it. And so what we did was we collected thousands of transcripts of like an entire agent trajectory and a permission prompt and had auto mode classify whether or not all safe. And it was extremely good at this. So then we got red teamers and we asked them to try to prompt inject and try to hack the codebase. And we use this to create evals and make sure that all of these were enough. And then we had our internal teams try to prompt inject and hack Claude Code's auto mode. So it's not only just protecting you against the vulnerabilities that are out there in the wild today, but the most intelligent attacks that we can construct.

### Context Engineering 哲學（16:45–18:10）

This is the thing, you know, people used to talk about prompt engineering. They used to talk about context engineering. This is sort of matching where the model was at the time. Back in the days of Sonnet 3.5, you had to prompt engineer. Back in the days of Opus 4, you had to context engineer. But with the models of today, you don't do any of this — you give it the minimal possible system prompt, the minimal possible tools. And then you let the model figure it out.

My general philosophy is tell the model only what it needs to know and let it figure out the rest of it. I think when you give the model too much context, it's kind of like you're micromanaging it. And sometimes the model knows the better way to get to the same outcome. And I personally prefer to give the model that freedom to do that.

### 手機遠端 + Agents 未來（15:45–18:45）

The thing that I would not have expected six months ago is probably half my engineering now is on my phone. I use a remote control, which is like amazing now. I'll just remote control in from my phone. I'll just like walk around, grab a coffee. And then I'll check in on my agents and maybe I'll start another agent. And sometimes I'm like talking to someone and we come up with a new idea. I'll just start an agent on the spot. I'll like talk to it with voice mode and just have it build something. And I don't even have to go back to my computer anymore.

Yeah, we're seeing these giant trends happening right now. Agents are running for longer. They're more autonomous. Very rarely am I running one agent at a time. It's usually like a few agents or dozens or hundreds or thousands. And so like the form factor for that, it's going to be really different than what came before.
