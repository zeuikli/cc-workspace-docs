## 分析摘要

**TL;DR**：綜合 Steinberger/Cherny/Felix Rieseberg 三人觀點，梳理 prompt→context→harness→loop 四級演進；Felix 的「tasks→responsibilities」升維是最重要的新洞察；附 comprehension debt、overbaking、Ralph Wiggum 等概念的歷史考古。

### 核心論點

1. **四級演進梯子（最可行動框架）**：
   - 任務是一句話 → 寫好 prompt
   - 任務塞不進一次對話 → 管理 context
   - 任務要跨小時、要驗證、要恢復 → 建 harness
   - 任務變成「持續發現活、持續干活」→ 寫 loop
2. **Felix Rieseberg 的升維（最重要洞察）**："Moving from giving AI tasks to giving it responsibilities"——三段論：提問→任務→責任；任務「從人開始，以人結束」；責任「人不在起點，也不在終點」；loop 是手段，responsibility 是本質
3. **Loop 考古**：Ralph Wiggum loop（Geoffrey Huntley，while true + Stop hook）→ Claude Code 官方插件 → Daniel Demmel 的 Feedback Loop Engineering → Steinberger/Cherny 集中發聲 → Addy Osmani 定名 Loop Engineering；「loop 不是靈光一現，是行業各自重新發明後的收敛」
4. **兩盆冷水**：
   - harness 沒有過時，loop 消費 harness（驗證器、狀態持久化、可觀測性全在 harness 裡）
   - comprehension debt（理解債務）：無人值守 loop 犯的錯誤無人讀，理解債務比技術債務涨得還快
5. **overbaking 失敗模式**：無監控 loop 可能花一整晚重構本來能跑的代碼庫繞過一個環境小錯誤

## 全文

6 月 7 日，OpenClaw 创始人 Peter Steinberger 发推：
> "You shouldn't be prompting coding agents anymore. You should be designing loops that prompt your agents."

几乎同时，Claude Code 负责人 Boris Cherny 在 Acquired 播客上说：
> "I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do. My job is to write loops."

这段剪辑迅速在 X 上刷屏（有转述称 24 小时内近 70 万播放）。

然后是 6 月 9 日，Claude Fable 5 发布。次日凌晨，Claude Cowork 的工程负责人 Felix Rieseberg 发了条 thread：
> "Its job is no longer to help me fix a crash, it's to keep our apps from crashing."

三个人、三条产品线（OpenClaw、Claude Code、Claude Cowork）、一周之内、同一个判断。

## 接着我之前那条演进线说

我之前写过：prompt engineering → context engineering → harness engineering，这条线背后的驱动力是任务尺寸。现在可以接上第四级了：

- 任务是一句话 → 写好 prompt
- 任务塞不进一次对话 → 管理 context
- 任务要跨小时、要验证、要恢复 → 建 harness
- 任务变成"持续发现活、持续干活" → 写 loop

Addy 给的定义很干净：loop engineering 就是把"负责 prompt agent 的那个人"换掉——你设计一个系统来代替你。loop 是一个递归目标：定义一次目的，AI 迭代直到完成。

典型形态：定时唤醒 → 读 CI 失败/issues/commits 找活 → 开独立 worktree 派 sub-agent 干活 → 第二个 sub-agent 对照测试做 review → 自动开 PR、更新 ticket → 搞不定的进人工收件箱 → 状态写进文件，明天接着跑。你设计一次。之后每一步，都不需要你 prompt。

## 但 loop 不是新发明，是被一步步"收编"的土方法

- 去年夏天，Geoffrey Huntley 提出 Ralph Wiggum 技术——while true + Stop hook 逼 agent 迭代
- 去年 12 月，Anthropic 把 Ralph 做成了 Claude Code 官方插件
- 今年 1 月，Daniel Demmel 写了《Feedback Loop Engineering》
- 6 月初，Steinberger 和 Cherny 集中发声，Addy 定名

loop 不是谁的灵光一现，是整个行业把同一个土办法各自重新发明了一遍之后的收敛。

## Felix 那半圈才是真正的升维

Steinberger 和 Cherny 说的是形态：循环地跑。Felix 说的是性质。他的原话：
> "Moving from giving AI tasks to giving it responsibilities."

他的三段论：第一阶段，提问；第二阶段，任务（每个任务"从人类开始，以人类结束"）；第三阶段，责任（人不在起点，也不在终点）。带过团队的人秒懂这个区别：交代任务要验收每一次；交付责任只看结果指标。loop 是实现手段，责任制才是本质——你不是在给 Claude 派活，你是在给它定 KPI、划地盘。

## 两盆冷水

**第一盆："harness 过时了"是误读。**
连定名者自己都没这么说。Addy 的原话是 loop "在 harness 之上一层楼"——还是那个 harness，只是它跑在定时器上、会派生帮手、会自我喂养。loop 是消费 harness 的：验证器、状态持久化、可观测性，这些脏活一件没少，全在 harness 里。

X 上有条回复说得很精准：agent loop 本质上就是带模糊状态转移的状态机，难的不是 loop 本身，是防止它因为一个无限重试 bug 烧掉 200 刀的 error boundary。

Huntley 给这个失败模式起过名：**overbaking（烤过头）**。没有监控的 loop，可能花一整晚重构一个本来能跑的代码库，就为了绕过一个环境小错误。

还有一个值得记住的新债务概念：**comprehension debt（理解债务）**。无人值守的 loop 会犯无人值守的错误，你不读它交付的东西，理解债务比技术债务涨得还快。

**第二盆：token 经济学。**
Addy 自己都说：这还很早期，他持怀疑态度，token 富裕和贫穷的人玩法会差得很远。Cherny 的 token 账单不用他自己付。你的归你。

## 我的判断

先把边界说清楚：这不是说以后所有场景都不写 prompt 了。一次性问题、探索性任务、低频任务，直接 prompt 仍然是最快的。loop 真正吃的是另一类活——重复、高价值、可验证、可恢复的任务。

模型每强一代，agent 能独立跑的时长就长一截，抽象单位就往上挪一格。Fable 5 这一代之后，loop 很可能从大佬的玩具，变成普通团队也值得排上日程的工程实践。

但注意 Demmel 在 1 月写下的那句话——比这波热潮早了四个月：
> prompt 和 harness 会随模型演进而变，紧凑反馈回路的价值不会变。就算 AI 泡沫下个月破了，你留下的也是易于测试的代码库。

可观测性、结构化日志、清晰接口、有用的报错——这些在任何人 prompt 任何模型之前，就已经是好的工程实践了。loop engineering 的入场券，还是那套没人爱干的基本功。新词会一直换。基本功不会。
