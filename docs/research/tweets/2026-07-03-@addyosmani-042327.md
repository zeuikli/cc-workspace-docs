## 全文摘要

**定位**：Agentic Engineering 成熟框架：6 階自主等級（Agency × Orchestration 雙軸）、Agent 執行合約、四大反模式、自主風險評估三問，以及 Anthropic 400K session 數據。

### 雙軸模型：Agency × Orchestration

**Agency 軸**（單 agent 深度）：
- Low：建議候選動作，等待決策
- Mid：執行任務，持續回報證據，可隨時調向
- High：以目標驅動，實驗/學習/測試，自主到完成才回報

**Orchestration 軸**（多 agent 廣度）：
- Low：單 agent，單 thread
- Mid：多 agent，各在獨立 worktree，目標相互隔離
- High：Orchestrator 從 backlog/issue tracker 生成連續工作，只在失敗時介入（"management by exception"）

### 六個自主等級

| 等級 | 名稱 | 核心特徵 | 驗證方式 |
|------|------|----------|----------|
| 0 | Assist | Autocomplete / inline 建議，人類決策 | 本地驗證 |
| 1 | Supervised action | Agent 執行但每步需確認，預設姿態 | Per-action approval |
| 2 | Scoped task delegation | 明確目標+約束+完成定義，人近旁可中斷 | 自動化測試/截圖/類型 |
| 3 | Goal-driven autonomy | `/goal /loop /schedule`，直到條件達標 | 可量化的成功條件 |
| 4 | Parallel delegation | 多 agent 平行，各有獨立 worktree 和 review queue | 所有權規則+合並控制 |
| 5 | Managed-by-exception | Manager agent 分派、監控、驗證、重試、升級 | 獨立驗證者+跨層 gate |

**三個時代**：駕駛座（0-1）→ 有界任務（2-3）→ 編排（4-5）

### ⚠️ 高自主系統三問

> 1. **我們多快知道做錯了？**（發現速度）
> 2. **我們多乾淨地能撤銷？**（可逆性）
> 3. **什麼能證明我們是對的？**（可驗證性）

若三個答案都是：不快、很困難、信任摘要 → 這不是真正的高自主。

### Agent 執行合約（8 欄位）

每次 agent run 前應定義：

| 欄位 | 說明 |
|------|------|
| Goal | 要達成的結果（非活動、非技術手段，是結果） |
| Scope | 操作域和允許的技術 |
| Non-goals | 目標以外的事項 |
| Tools & Permissions | Agent 與世界互動的方式 |
| Stopping condition | 何時停止（最好是可量化變數） |
| Evidence | 可獨立確認任務完成的具體測試/截圖/日誌/數據庫記錄 |
| Escalation | 什麼情況涉及誰（包括誰運行 agent） |
| Budget | 時間/effort/token 上限（可加嘗試次數和並行度限制） |

### 四大反模式

**1. 自主性即地位（Autonomy as Status）**
症狀：更高自主性被視為能力象徵，agent 跑得比驗證支撐的更熱。
修復：獎勵「選對自主等級」行為，而非「跑最高等級」。

**2. 許可清洗（Permission Laundering）**
症狀：審批疲勞導致授予 agent 遠超必要的寬泛訪問權。
修復：沙盒 profile、scoped writable roots、allowlisted commands、hooks、Auto-review。

**3. 摘要替換（Summary Substitution）⚠️**
症狀：Agent 的工作摘要替代了實際 review，假設摘要就夠了。
修復：驗證包要含 diff + 測試 + 日誌 + 截圖 + 審查發現 + 風險 + 缺口，**不接受認知投降**。

**4. 艦隊扮演（Fleet Cosplay）**
症狀：幾十個 agent 並行，但人類仍手動協調所有依賴。
修復：共享狀態、所有權規則、依賴追蹤；縮小 WIP 迫使記錄協作步驟直到編排自動化。

### Anthropic 400K Sessions 數據

研究範圍：2025-10 至 2026-04，~400K sessions，~235K 用戶：
- 人類做 ~70% 的**規劃決策**
- Claude 做 ~80% 的**執行工作**
- 「高自主不是把人排除在外，而是從做每一步 → 決定下一個方向」

### 驗證始終是瓶頸

**「The bottlenecks are coordination, verification, maintenance, product judgment and incident learning.」**

建議追蹤的自主指標：
- 介入間平均時間（Mean time between interventions）
- 最長無人值守成功 run（Longest successful unattended run）
- 沙盒 vs 升級比例
- 自動批准 vs 拒絕百分比
- 每個人類指令的 agent 動作數
- 每個接受變更的 review 時間
- 每個置信等級的返工率

**「Verification will always be the bottleneck.」**

## 研究摘要

**TL;DR**：Agentic Engineering 最完整自主等級框架：6 等級 / 雙軸（Agency×Orchestration）/ 三個時代 / Agent 執行合約 8 欄位 / 四大反模式（Summary Substitution 最關鍵）/ 高自主三問 / Anthropic 400K session 數據；「驗證是永遠的瓶頸」。

### 核心論點

- **雙軸模型**：單 agent 深度（Agency）與多 agent 廣度（Orchestration）是正交維度，一維梯子無法捕捉
- **Summary Substitution 反模式**：Agent 摘要 ≠ 驗證，必須要求證據包（diff/tests/logs/screenshots）
- **三問框架**：「多快知錯 / 多乾淨撤銷 / 什麼能證明對」是真正高自主的可行驗證標準
- **人類在高自主中的角色**：從做每一步 → 決定下一個方向（70% 規劃 / 80% 執行由 Claude）
- **Fleet cosplay 陷阱**：有多個 agent 但沒有真正的所有權/狀態管理 = 假 orchestration

### 關鍵數據 / 工具

- Anthropic 研究：~400K sessions, ~235K 用戶（Oct 2025–Apr 2026）
- 人類 70% 規劃 / Claude 80% 執行
- 6 等級 × 8 欄位 Agent 合約（結構化 handoff）
- 自主度量指標清單（8 項）

### 批判性觀察

- Summary Substitution 與 workspace 的 unverified_success 閘門完全對齊，是本文最直接的規則強化
- Agent 執行合約（8 欄位）是 delegation-protocol.md 的高品質補充
- 雙軸模型給「委派決策」增加了正交性分析（單 agent 深度 vs 多 agent 廣度）
- 400K sessions 數據是本批次 19 篇文章中唯一的大規模實證數據
- 文章明確標注「100% human-written」（Pangram 驗證），可信度高
