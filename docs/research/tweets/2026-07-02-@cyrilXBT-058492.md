## 全文摘要

**定位**：Anthropic 官方 prompting guide 完整解碼，含 API 級別技術細節、10+ 個直接可用的 prompt 模板，以及 Fable 5 遷移 checklist。

### 最大行為變化：回應時間

- high effort：單次回應可達數分鐘
- 自主 run：可達數小時
- **API 遷移警告**：為 Opus 4.8 設定的 timeout 必定太短，需重新審計所有 timeout 設定

### Effort 控制方法

| 方式 | 觸發 | 效果 |
|------|------|------|
| prompt 含 `ultrathink` | 單次請求 | xhigh 推理 effort |
| Claude Code `/effort ultracode` | 整個 session | xhigh + 自動 dynamic workflow 編排 |
| API `effort` 參數 | 每次請求 | 直接指定 |

**⚠️ 重要**：`ultracode` 需要支援 xhigh effort 的模型（Fable 5 / Opus 4.8 / Opus 4.7），Sonnet 4.6 及更早版本不支援。

**Thinking display 設定**：`thinking.display = "summarized"` 返回可讀摘要；`"omitted"`（默認）返回空 thinking 欄位。Raw chain of thought 在 Fable 5 永不返回。

### 進度驗證 Prompt（最關鍵技術）

Anthropic 測試：以下措辭幾乎消除長 agentic run 的虛假進度報告，**「audit」語言優於更溫和的等效說法（Anthropic 測試多個版本確認）**：

```
Before reporting progress, audit each claim against
a tool result from this session. Only report work
you can point to evidence for. If something is not
yet verified, say so explicitly. Report outcomes
faithfully: if tests fail, say so with the output.
If a step was skipped, state that. When something
is done and verified, state it plainly without hedging.
```

**建議**：寫入 system prompt，對任何超過幾分鐘或涉及 tool 執行的 workflow 都要加。

### 主動性問題（Proactivity Constraint）

Fable 5 比 Opus 4.8 更主動，會採取未被要求的行動（起草 email、建 git 備份分支）。針對所有自動化/無人值守 workflow 的 system prompt 加入：

```
When the user is describing a problem, asking a question,
or thinking out loud rather than requesting a change, the
deliverable is your assessment. Report your findings and
stop. Do not apply a fix until asked. Before running a
command that changes system state, including restarts,
deletes, or config edits, confirm that the evidence
actually supports that specific action.
```

### 記憶系統 Prompt

```
Maintain a memory system in [folder]. Store one lesson per
file with a one-line summary at the top. Record corrections
and confirmed approaches alike, including why they mattered.
Do not save information already in the repo or chat history.
Update existing notes rather than creating duplicates.
Delete notes that have proven incorrect.
```

Session 結束時：
```
Reflect on the sessions we have had. Use subagents to
identify core themes and lessons, and store them in [folder].
Reference [folder] at the start of future sessions.
```

### Final Response 格式指令（長 run 後）

```
For your final response after this task: state the outcome
first, then the key supporting details. Do not include working
abbreviations, internal labels, or arrow chains in the
user-facing output. Users need the outcome, the evidence,
the risks if any, and the next step.
```

→ 將模型內部工作過程與最終用戶看到的輸出分離。

### Sub-Agent 委派模式

三條需同時使用的指令：
```
Delegate independent subtasks to sub-agents and continue
working while they run. Each sub-agent should receive a
specific, bounded scope and explicit success criteria.
Synthesize sub-agent results only after all have reported.
If any sub-agent fails or cannot complete its scope, report
that clearly in the synthesis rather than inferring what
would have been found.
```

**關鍵最後一行**：**子代理失敗 = 資訊，不得推斷**。綜合報告必須如實反映失敗。

### 安全分類器與 API 錯誤處理

**⚠️ 拒絕 = HTTP 200，非錯誤**：
- `stop_reason: "refusal"` 是成功的 API 調用，需獨立於 HTTP status 檢查
- Anthropic 提供 SDK middleware 用於自動 fallback 到 Opus 4.8（prompt-cache 費用在無輸出的拒絕中不計費）
- 拒絕率：典型開發者查詢 <5%，但可出現在涉及生物/代碼審查敏感域的正常任務中

### Vision Prompting（升級後）

**關鍵觸發語句**：加入「crop and zoom」觸發 bash 工具處理噪雜圖像：
```
Here is the design target and a screenshot of the current
implementation. Use vision to identify differences and
generate the changes needed to close the gap. Crop and zoom
into any areas where the comparison is unclear before
reporting findings.
```

Fable 5 可用 vision 評估自己的輸出（設計稿 vs 截圖 → 識別差異），關閉了以前需要人工視覺比對的迴路。

### Fable 5 遷移 Checklist

1. **Timeouts**：為 Opus 4.8 設定的 timeout 全部太短，必須延長
2. **Refusal handling**：API response 解析需獨立檢查 `stop_reason: "refusal"`，設置 Opus 4.8 fallback
3. **Proactivity constraints**：所有自動化/無人值守 system prompt 加入邊界塊
4. **Progress verification**：所有超 5 分鐘或涉及 tool 執行的 workflow 加入 audit 指令
5. **Memory structure**：跨 session workflow 設置 lesson file 結構
6. **Final response format**：所有直接輸出給用戶的 workflow 加入 outcome-first 指令
7. **Testing scope**：用至少一個 Opus 4.8 無法完成的任務測試，驗證遷移是否有實質改善

## 研究摘要

**TL;DR**：Anthropic 官方 Fable 5 prompting guide 最完整解碼：`ultrathink`/`ultracode` 關鍵字、HTTP 200 拒絕處理、「audit」語言驗證效果最佳、子代理失敗禁止推斷、vision crop-and-zoom、7 項遷移 checklist。技術深度最高，直接可套用。

### 核心論點

- **ultrathink** = prompt 層面的 xhigh effort 觸發；**ultracode** = session 級 xhigh + 自動 dynamic workflow
- **「audit」語言**是進度驗證最有效措辭（Anthropic 多版本測試確認）
- **子代理失敗 = 資訊**：不得推斷失敗子代理的結果
- **API refusal = HTTP 200**：需獨立解析 stop_reason，不是 HTTP 錯誤
- Vision 的「crop and zoom」指令觸發 bash 預處理噪雜圖像

### 關鍵數據 / 工具

- `ultrathink`：單次 xhigh prompt 觸發詞
- `/effort ultracode`：session 級 xhigh + 動態 workflow（僅限 Fable/Opus 4.8/4.7）
- 拒絕率：<5% 典型開發者查詢
- 遷移 7 項 checklist（直接可用）

### 批判性觀察

- 本文是本批次工作區可行動性最高的文章之一
- ultrathink/ultracode 在其他文章未見，是操作級新發現
- HTTP 200 refusal 處理是 API 整合的關鍵漏洞點
- Final response format 指令（outcome-first）與 workspace overnight 總結風格高度吻合
- Sub-agent 失敗禁止推斷對齊 core.md 的 unverified_success 閘門
- Vision 部分在本批次 19 篇文章中最有深度
