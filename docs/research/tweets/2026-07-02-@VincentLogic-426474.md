## 全文摘要

**定位**：反直覺建議：使用 Fable 5 的最高槓桿用法不是生成更多成品，而是清理過去幾個月積累的「AI 工作負債」，建立持久系統。

### AI 工作負債（AI Work Debt）

混亂的 Memory、重複的長期指令、互相衝突的 Rules、邊界不清的 Skills，以及沒有審核機制的工作流。

**根本原因**：
- 每次模型犯錯 → 臨時增加一條規則
- 需求改變 → 補充新指令
- 這些補丁從不清理 → 時間一長，重複規則、過期信息、衝突指令全堆在一起
- 「模型沒有變，工作環境變亂了。」

### AI 工作系統三層結構

| 層次 | 內容 | 特性 |
|------|------|------|
| **第一層：長期上下文** | CLAUDE.md、Auto Memory、按條件加載的 Rules | 決定 session 開始時 Claude 能看到什麼 |
| **第二層：Skills** | 特定任務的知識/清單/步驟/工具 | 主動沉澱；觸發前只載入名稱+描述；問題在描述不清/邊界混亂 |
| **第三層：審核機制** | 事實/邏輯/格式/風險/完成標準的檢查 | 需要預先定義，不依賴生成 agent 自我評估 |

**判斷規則**：如果你反複把同一套清單/指令粘進對話，或 CLAUDE.md 某段變成「操作流程」→ 拆成按需調用的 Skill。

### Fable 5 視窗三件事

**一、清理上下文負債**

讓 Fable 5 審計的七類問題：
- 重複或語義相近的規則
- 互相矛盾的新舊指令
- 已過期的信息
- 被誤寫成全局規則的項目要求
- 應該遷移到 Skill 的多步驟流程
- 描述含糊/邊界不清/容易誤觸發的 Skills
- 沒有明確完成標準的要求

**⚠️ 重要**：不要讓模型未經確認就直接覆蓋文件。先輸出問題清單 + 推薦結構 + 修改 Diff，人工審核後再更新。

**二、沉澱可複用資產**

從聊天記錄中提取（不是原封不動塞進 Memory）：
- 知識庫、Skills、內容模板、操作手冊、決策記錄、常見錯誤清單
- 「如果來不及完成任務，至少留下流程、模板、檢查清單和完成標準」

**三、建立獨立審核系統**

**獨立 Agent 分工（避免自我讚美）**：
- 生成 Agent：只負責寫
- 審核 Agent：只負責挑錯
- 編輯 Agent：只負責調整節奏
- 事實檢查 Agent：只負責核對來源
- 人工：決定能否發布

> 「不要讓同一個 Agent 寫完文章後，再問它：你覺得這篇有沒有問題？它很容易沿著自己的思路，再次證明自己沒錯。」

### 直接可用審計 Prompt

```
请对我现有的 Claude Code/Cowork 智能体系统进行完整审计。
检查范围包括：CLAUDE.md、Rules、Skills、Auto Memory、
Subagent 配置、审核标准和工作流文档。

请识别：
- 重复或语义相近的规则
- 互相矛盾的指令
- 已经过期或缺少适用范围的信息
- 应该迁移到 Skill 的多步骤流程
- 描述模糊、边界不清或容易误触发的 Skills
- 缺少验证方式的关键要求
- 可以改造成测试、Hook、清单或 Reviewer Agent 的内容

先不要修改文件。请输出当前结构、问题清单、风险等级、
推荐结构和迁移方案。每项修改都要说明理由，并以 Diff 形式
供我审核。对于无法确定的信息，请明确标记，不要自行删除。
```

## 研究摘要

**TL;DR**：使用 Fable 5 的最高槓桿用法是清理「AI 工作負債」（混亂 Memory/衝突 Rules/邊界不清 Skills）；三層結構（長期上下文/Skills/審核機制）；獨立審核 agent 分工；提供直接可用審計 prompt（輸出問題清單+Diff，不直接覆蓋文件）。

### 核心論點

- **「模型沒有變，工作環境變亂了」**：模型性能下降通常是 context debt 而非模型退化
- **三層結構**清晰對應 workspace 的 CLAUDE.md/Skills/hooks 分工
- **獨立審核 agent 分工**：生成/審核/編輯/事實檢查/人工決策，防止自我讚美循環
- **Diff 優先**：審計輸出 Diff 而非直接修改，對齊 APPLY 前 gate 原則

### 關鍵數據 / 工具

- 三層結構：長期上下文 / Skills / 審核機制
- 七類 context debt 問題清單
- 審計 prompt（輸出結構：問題清單 + 風險等級 + 推薦結構 + Diff）
- 實際案例：GiftX 項目中使用 Fable 5

### 批判性觀察

- 「AI 工作負債」框架對 workspace 維護協議高度適用
- 審計 prompt 的「先不修改，輸出 Diff 讓人審核」直接對應 core.md §APPLY
- 獨立審核 agent 分工在中文 AI 創作場景有具體操作路徑
- 七類 context debt 問題清單可直接納入 maintenance-protocol.md
- 文章較短（3199 字），缺少技術實作細節；基於個人項目經驗，無定量數據
