## 全文摘要

**定位**：14 步構建 Fable 5「自我改進系統」的完整路線圖，三層架構（原語層／Orchestration 層／Self-improvement 層）+ Memory 五階段進化模型 + Maker/Verifier 分離原則，含 Anthropic Parameter Golf 實驗數據。

### 核心概念澄清

**Self-improving ≠ Self-learning**
- Self-learning（不是 Fable 5 做的事）：模型改變自己的權重，變得更聰明
- Self-improving（Fable 5 的實際方式）：模型本身不變，但周圍系統（Memory/Skills/Workflow）持續積累優化
- 「模型是無狀態的，但系統是有狀態的」

### 四層架構（複利增長）

| 層次 | 內容 | 類比 |
|------|------|------|
| **第 1 層（原語層）** | Fable 5 模型、基礎工具、簡單對話 | 厲害員工但無工作流程/模板/標準 |
| **第 2 層（Orchestration 層）** | /goal、動態 Workflow、Routines | 配備項目管理工具和自動化腳本 |
| **第 3 層（Memory 層）** | STATE.md、Skills 庫、知識庫 | 筆記本、工作手冊、經驗總結 |
| **第 4 層（Self-improvement 層）** | 自我檢查輸出→提炼教訓→寫回 Skills→閉環 | 員工反思更新工作手冊，能力複利增長 |

### 四模型路由（成本控制）

| 模型 | 角色 | 使用場景 | 成本 |
|------|------|----------|------|
| **Fable 5** | 項目經理（Orchestrator） | 複雜多天項目、整體規劃 | $$$ |
| **Opus 4.8** | 技術專家（Fallback） | 架構決策、複雜調試 | $$ |
| **Sonnet 4.6** | Worker | 日常代碼、重構、文檔 | $ |
| **Haiku 4.5** | Grader | 快速驗證、簡單分類 | $ |

**黃金組合**：`Fable 5 Orchestrator + Sonnet Worker + Haiku Grader + Opus Fallback`（Anthropic 內部使用）

### 三個 Primitives（讓系統「活」起來）

**05 · Loop 機制（/goal + Outcomes）**
- 設定明確 Goal → 獨立 Grader 檢查 → 未達標自動下一輪優化 → 達標退出
- `/goal`（Claude Code 本地）vs `Outcomes`（CMA 雲端，適合 GPU/Sandbox 任務）

**06 · Maker/Verifier 分離（強制要求）**
- Anthropic Parameter Golf 實驗：有獨立 Verifier 的 Fable 5 → 約 6 倍於 Opus 4.7 的改進
- 無 Verifier 的 Opus 4.7 → 保守小改動，遇負面結果即停
- 有 Verifier 的 Fable 5 → 敢於大膽架構改變，持續探索直至最優

**07 · 動態工作流（三種模式）**
1. **Fan-out and Synthesize**：大任務拆分平行，綜合結果（20 個規則 → 20 個平行 Verification Agent）
2. **Adversarial Verification**：自動生成「攻擊者 Agent」找 Bug，完全不知道 Maker 思路
3. **Loop Until Done**：跑測試→失敗分析修復→再跑，循環直到全通過

**08 · Git Worktrees（防文件衝突）**
- 多 Agent 並行時，各 Agent 在獨立 worktree 工作，完成後合並
- 場景：Maker/Verifier 隔離 / 並行實驗 / 長期項目 Checkpoints

**09 · Routines（三種觸發方式）**
- **Scheduled Triggers**：每天定時自動運行（重跑測試、更新 Skills、發 Slack 摘要）
- **API Triggers**：CI 失敗/服務報警時自動響應
- **GitHub Triggers**：PR 提交/合並後自動評估/提炼模式到 Skills 庫

### Memory 五階段進化模型

| 階段 | 名稱 | 行動 | 例子 |
|------|------|------|------|
| **Stage 1** | Failure | 記錄失敗 | 「查詢返回空結果」 |
| **Stage 2** | Investigation | 追根溯源 | 「字段名錯了，用了 prc_usd 但實際是 prc」 |
| **Stage 3** | Verification | 確認已驗證事實 | `SELECT MIN(prc), MAX(prc) FROM trades` 確認字段 |
| **Stage 4** | Distillation | 提炼通用規則 | 「查詢時間分桶時始終指定時區」 |
| **Stage 5** | Consultation | 下次主動查閱規則 | 再次查詢時自動應用「時區規則」 |

**各模型實驗數據（Anthropic）**：
- Sonnet 4.6：停在 Stage 1（記錄失敗，不深入調查）
- Opus 4.7：到達 Stage 3，驗證覆蓋率 17%（30 個問題中驗證 5 個）
- Fable 5：完成全部五階段，驗證覆蓋率 73%（30 個問題中驗證 22 個）

### STATE.md 結構（六分區）

```
# 項目記憶 · [項目名]

## 已驗證的事實（Stage 3 — 不再猜測這些）
- 欄位/數值/配置，附驗證命令和確認日期

## 通用規則（Stage 4 — 先查閱再行動）
- 可應用到其他場景的原則

## 待調查的失敗（Stage 1→2）
- 已知失敗 + 假設 + 重現步驟

## 經驗教訓（Stage 4 的提煉）
- 踩坑記錄 + 解決方案

## 上次會話（Stage 5 — 恢復點）
- 時間戳 + 已完成 + 下一步
```

**兩個黃金規則**：① 離開前必須寫入；② 開始前必須讀取

### STATE.md vs Skills 分工

| 類型 | 範圍 | 生命週期 | 例子 |
|------|------|---------|------|
| **STATE.md** | 項目特定 | 隨項目結束 | 「這個項目的 prc 字段是美元」 |
| **Skills** | 跨項目通用 | 永久（`~/.claude/skills/`） | 「處理價格字段時，始終驗證單位」 |

### Visual Verification（視覺驗證）

- Fable 5 可截圖→視覺能力「看」截圖→對照設計要求→描述具體差距→返回 Maker
- 適用場景：UI 實現驗證、數據可視化、設計保真度檢查
- Parameter Golf 實驗：Fable 5 自己看訓練曲線圖判斷是否收斂，無需人類看圖表

### Safety Boundaries（安全分類器）

分類器觸發後返回 HTTP 200（`stop_reason: "refusal"`，非 HTTP 錯誤）：
- 網絡安全漏洞研究
- 生物學
- 化學
- 模型蒸餾

**設計原則**：必須為這些域設計 fallback 機制 + 不同 Agent 進行安全分析 + 測試用無害替代品

## 研究摘要

**TL;DR**：Fable 5 「自我改進系統」完整 14 步路線圖（簡中）：Self-improving≠Self-learning 澄清、四層架構、四模型路由（Orchestrator/Expert/Worker/Grader）、Memory 五階段進化（Failure→Distillation→Consultation）、STATE.md 六分區模板、Skills vs STATE.md 分工、Maker/Verifier 分離（+6x 改進數據）、三種 Routine 觸發方式、Git Worktrees 隔離、Visual Verification、Safety Boundary 設計。

### 核心論點

- **Self-improving ≠ Self-learning**：模型無狀態，系統有狀態——Memory/Skills 積累才是複利增長的本質
- **Memory 五階段**：Sonnet=Stage1/Opus=Stage3(17%)/Fable=Stage5(73%)——驗證覆蓋率差距體現在 Stage3 Verification
- **Maker/Verifier 分離**：結構性分離（不同 Agent、不同 worktree、不同上下文）產生 6x 改進
- **STATE.md 是恢復點**：沒有「開始前讀取」→ Fable 5 退化到 Sonnet 級別記憶表現
- **四模型路由**：Fable 5 最貴，只用於需要多天持續協調的任務

### 關鍵數據 / 工具

- Parameter Golf 實驗：8×H100，8 小時，Fable 5 with Verifier = 6x 改進 vs Opus 4.7
- Memory 驗證覆蓋率：Sonnet≈0%、Opus 4.7=17%、Fable 5=73%
- STATE.md 六分區模板 + CI triage Skills 演化範例
- 三種 Routine 觸發（Scheduled/API/GitHub）

### 批判性觀察

- Memory 五階段模型（Stage1~5）與 workspace 的 MEMORY.md + LESSONS.md 分工高度對齊
- Maker/Verifier 分離強化 subagent-strategy.md 的「child 不 self-retry」原則
- STATE.md 六分區結構可作為 MEMORY.md 的項目級模板補充
- 四模型路由 Grader 角色（Haiku 做快速驗證）補充 delegation-protocol.md
- Safety classifier fallback 設計原則補充 error-handling 規範
- 文章為簡體中文，受眾為中文用戶；內容原創性高，大量引用 Anthropic 官方實驗數據
