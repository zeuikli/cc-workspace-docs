## 分析摘要

**TL;DR**：Agent loop 入門概念指南：loops vs workflows（loop 根據反饋適應）、open vs closed loops、evals > prompts、memory + skills 的角色；核心洞察「eval 決定 loop 有沒有用，沒有 eval = recursion not improvement」。

### 核心論點

1. **Loop vs Workflow 區別**：workflow 跟隨預設序列；loop 根據反饋適應——prompt 問「下一步是什麼」；loop 問「完成了嗎」並持續跑到答案是 yes
2. **五個基本元素**：goal / context / execution / evaluation / stopping conditions；沒有 evaluation 就沒有 loop；沒有 stopping condition 就沒有終點
3. **Evals 比 Prompts 重要（最重要洞察）**：
   - 無 evals：agent → agent → agent = recursion（遞迴，非改進）
   - 有 evals：agent → evaluation → feedback → agent = improvement
   - 「evals are becoming the new prompts」
4. **Open loop vs Closed loop**：open loop 可探索新方法但成本爆炸（若 eval 弱則成為 expensive slop generator）；closed loop 有邊界，可重複，大多數 production 系統選此
5. **Memory + Skills 角色**：loop 是過程；memory 是持久化（沒有 memory 每次從零開始）；skills 讓 loop 複利（solve→save→reuse 替代 solve→forget→solve）

2. 「evals are becoming the new prompts」是觀察入微的句子，但作者未展開如何設計 evals

## 全文

## we spent 2 years learning prompts. now we're learning loops.

you gave the agent a task - it gave you an answer. then you decided what happened next.

the agent was doing the work. you were doing the orchestration. this works for simple tasks. it breaks down the moment a task becomes iterative.

agent looping is the process of replacing yourself as the person deciding the next prompt. instead of manually steering every step, you build a system that repeatedly evaluates progress and generates the next action until a goal is reached.

a prompt is a single move. a loop is a strategy.

a prompt asks: what should happen next? a loop asks: are we done yet? and keeps running until the answer becomes yes.

at its simplest, every loop contains five parts: goal / context / execution / evaluation / stopping conditions.

without an evaluation there is no loop. without a stopping condition there is no end.

## workflows vs loops

a workflow follows a predefined sequence. a loop adapts based on feedback. a workflow follows instructions. a loop reacts to outcomes.

that is why loops tend to perform better on messy problems where the path is unknown.

## open loops vs closed loops

**Open loops** are exploratory. The goal exists. The evaluation exists. But the path is flexible. The system can discover new approaches, create new subtasks, test multiple solutions. This is where some of the most exciting agent research is happening. It is also where costs explode. Open loops maximize discovery. But they can easily become expensive slop generators if the evaluation layer is weak.

**Closed loops** are bounded. The agents still loop. But they loop inside a structure. They improve through repetition without wandering into nonsense. Most production systems today are closed loops. They are cheaper. More predictable. And easier to verify.

## why evals matter more than prompts

Most people think loops make agents smarter. They don't. Evals make loops useful.

Without evals: agent → agent → agent → agent. You get recursion.

With evals: agent → evaluation → feedback → agent. You get improvement.

The evaluation layer decides whether the output is acceptable, whether another iteration is needed, whether the system should stop.

In many ways, evals are becoming the new prompts.

## where memory fits

A loop is the process. Memory is persistence. Without memory, every run starts from zero. With memory, the system accumulates knowledge over time.

Memory can be: markdown files / databases / linear boards / vector stores / knowledge graphs. The implementation changes. The principle stays the same. The agent forgets. The system remembers. Memory is what allows loops to survive beyond a single conversation.

## skills are where loops compound

A loop without skills has to rediscover everything every run. A loop with skills gets stronger over time. A skill is simply reusable knowledge.

Without skills: solve → forget → solve → forget → solve.
With skills: solve → save → reuse forever.

This is how loops start compounding instead of just consuming tokens.

## what is loop engineering?

Agent looping is the mechanism. Loop engineering is the discipline. You are no longer programming the agent directly. You are programming the environment around it.

The leverage point moves from: what prompt should I write? to: what system should I build?

The biggest challenge: cost. Loops are expensive. A loop without guardrails can burn tokens indefinitely.

we spent the last two years learning how to talk to agents. the next few years will be spent learning how to build systems that talk to them for us.
