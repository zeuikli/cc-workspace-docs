## 全文

You get good results from Claude by doing two things: controlling what it reads, and giving it a way to check its own work. The 10 moves below build on that. Most come from Anthropic's engineering teams and their docs.

---

## 1. Give Claude a memory file

In Claude Code, a CLAUDE.md at your project root loads at the start of every session. Write your build commands and known gotchas into it. On claude.ai, a Project does the same job. Upload your style guide or codebase, add custom instructions, and skip re-explaining yourself every chat.

Keep it short. For each line, ask whether cutting it would make Claude slip. If not, cut it. Claude ignores a bloated file.

---

## 2. Clear context between tasks

Claude's context window holds the whole conversation, and quality drops as it fills. Run /clear in Code, or start a fresh chat on claude.ai, when you move to an unrelated task. Corrected Claude twice on the same bug? Clear the context and rewrite the prompt with what you learned. A short clean session gives you better code than a long cluttered one.

[圖 2]

---

## 3. Explore, then plan, then code

Let Claude jump straight to code and it often builds the wrong thing. Use plan mode instead: Claude reads the relevant files and writes a plan before it changes anything. Edit the plan, then let it build. Skip the step for one-sentence fixes.

[圖 3]

---

## 4. Teach Claude once with skills

A skill is a folder you drop into .claude/skills/. Put your conventions in a SKILL.md and Claude loads it when a task calls for it. Anthropic runs hundreds of them in production. Spend your effort on the Gotchas section, the real mistakes Claude makes with your code. Write them down and it stops repeating them.

[圖 4]

---

## 5. Give Claude a way to check itself

Claude stops when the work looks done to it. Hand it a test suite or a screenshot to compare against, and it closes the loop alone: write, run, read the result, fix again. With no check, you turn into the test harness and catch every mistake by hand.

[圖 5]

---

## 6. Push research into subagents

Claude reads dozens of files when it explores a codebase, and each one fills your context. Tell it to use subagents to investigate the question. The subagent works in its own window and reports back a summary, so your main session stays clear for the build.

[圖 6]

---

## 7. Lock the rules you can't break with hooks

Claude follows CLAUDE.md instructions about 70% of the time. Hooks run as scripts at fixed points in the workflow and fire on 100% of runs. Save them for the rules you can't bend: auto-format after an edit, or block a push to main.

[圖 7]

---

## 8. Front-load your prompt

Claude Opus 4.8 reasons more after each of your turns, and that burns tokens. Pack the task and its constraints into your first message instead of drip-feeding them over many turns. You trade a dozen small exchanges for one big one: fewer round trips, lower cost, steadier work on long jobs.

[圖 8]

---

## 9. Reach for CLI tools

CLI tools cost Claude the fewest tokens when it works with outside services. Install the gh CLI and Claude opens PRs and reads issues without tripping API rate limits. It also learns tools it doesn't know yet: point it at foo --help and let it work out the rest.

---

## 10. Let Claude interview you

For anything past a quick fix, flip the roles. Ask Claude to interview you about edge cases and tradeoffs before it writes a line, then have it save your answers to a SPEC.md. Start a fresh session and build from that spec. On the Console, the prompt improver runs the same polish over your prompts in under a minute.

---

Do this and you spend your time reviewing Claude's work instead of redoing it. Like and repost if you found this helpful.

## 研究摘要

**TL;DR**：控制 Claude 讀到的內容、給它自我驗證的方式，是高效使用的兩大核心，10 個技巧從記憶檔到 CLI 工具全方位覆蓋。

### 核心論點

1. **CLAUDE.md / Project 記憶**：session 開頭載入，短而精準；每行問「刪掉 Claude 會犯錯嗎」，不會就刪
2. **Context 管理**：換任務就 /clear，短乾淨 session > 長雜亂 session；同一 bug 糾正兩次 → 清 context 重寫 prompt
3. **Explore → Plan → Code**：先讓 Claude 讀檔寫計畫，再執行，避免直接 code 建錯方向
4. **Skills（.claude/skills/）**：封裝慣例，Gotchas section 記錄真實錯誤，Anthropic 生產環境跑數百個
5. **Hooks vs CLAUDE.md**：CLAUDE.md 遵循率 ~70%，Hooks 100%，關鍵不可違規則用 Hooks 鎖定
6. **反向採訪模式**：讓 Claude 採訪你邊界案例後存 SPEC.md，再建 fresh session 依 spec 實作

### 關鍵數據 / 工具

- CLAUDE.md 遵循率：~70%；Hooks：100%（作者經驗估計）
- Claude Opus 4.8：每輪推理消耗 tokens → 需要 front-load prompt
- 工具：`.claude/skills/`、`gh CLI`、`SPEC.md`、`/clear`、Plan Mode
- 來源：Anthropic 工程團隊與官方文件

### 批判性觀察

1. 多數技巧是 Anthropic 官方最佳實踐的整理，創新性偏低，但品質一致且可直接套用
2. CLAUDE.md 70% vs Hooks 100% 的數字未提供明確來源，為作者經驗估計，實際遵循率可能因任務類型差異
3. 技巧 10「讓 Claude 採訪你 + SPEC.md」是少見的反向工作流，對熟悉 Claude 的用戶有高實用性，但學習門檻略高
