# WHY YOUR TOKENS DISAPPEAR

Let's start by figuring out why your tokens disappear so fast.
Every time you send a message, the model doesn't just process your latest prompt. It re-reads everything:
- every file you attached
- every previous message
- every tool result

And the bigger your chat history, the more files you attach - the more tokens you burn.

[圖 1 — 來源: Token burn per message graph.]

## Mistakes almost everyone makes

The first mistake
```json
→ ask "what does this function return?"
→ model thinks at High effort
→ burns reasoning tokens on a 2-second question
→ repeat 50 times a day
```

You just spent Max-level thinking on a question that needed none.

The second mistake: cranking everything to Max "to be safe"
```json
"I'll just set it to max so I get the best answer"
→ every prompt now burns 4-8x more tokens
→ even when the task is trivial
→ limit hits in 30 minutes
```

Using Max effort on trivial tasks is a waste, you're paying for thinking power you're not using.

Third mistake: never compacting
```json
By message 40, the model re-reads thousands
of tokens of history every single turn.

You're paying for the same context over and over.
```

The rate is identical at every effort level - $5/$25 per 1M tokens.
You don't pay more per token for thinking harder. You pay because the model generates more tokens.
You should spend tokens where they matter, save them where they don't.

# EFFORT CONTROL

This is the feature that saves you the most tokens.
Opus 4.8 lets you control how much thinking it puts into each task.
Five levels:
```json
/effort low      # quick questions, formatting, lowest token use
/effort medium   # everyday coding, balanced
/effort high     # default, solid reasoning
/effort xhigh    # deeper, for complex code and agents
/effort max      # maximum, no token cap
/effort auto     # let the model decide
```

In Claude .ai and Cowork it's a slider next to the model picker:
Low → Medium → High → Extra → Max

In Claude Code it's the commands above. "Extra" in the app and "xhigh" in Claude Code are the same level - just different labels.

How much each level actually costs:
```
Level      Thinking depth     Token spend     Best for
Low        minimal            ~0.1x           formatting, simple questions
Medium     moderate           ~0.4x           routine edits, drafts
High       solid              1x (baseline)   daily coding (default)
Extra      deeper             ~2-3x           complex code, agents
Max        maximum            ~4-8x           heavy architecture
```

Real money example:
A High answer costs ~$0.05
A Low answer costs ~$0.005
A Max answer costs ~$0.20-0.40

The move is simple: Stop leaving everything on one level.
Route effort per task: Small stuff on Low, daily work on High and only THE HARDEST PROBLEMS on Max.
That one habit alone is the difference between hitting your limit in 30 minutes and working comfortably all day.

# FAST MODE

Fast mode runs Opus 4.8 at 2.5x speed and it's now 3x cheaper than it used to be.
```json
Standard Opus 4.8:    $5 / $25 per 1M tokens
Fast mode:            $10 / $50 per 1M tokens (2.5x speed)
Previously:           $30 / $150 per 1M tokens
```

Fast mode used to cost $30/$150 - six times more than standard. Now it's only double the rate for 2.5x the speed. For the right tasks, that's a straight upgrade.

Toggle it in Claude Code:
```json
/fast
```

When to use it:
- large multi-file refactors
- code generation from a spec
- documentation and test generation

Basically anything where the model already knows what to do and just needs to do it fast.

When to avoid it:
- complex debugging
- architecture decisions
- security review

The combo that actually saves tokens: use fast mode for bulk work (refactors, tests, docs) and standard High for thinking work (debugging, architecture). Match the mode to the job - speed where you want it, depth where you need it.

# DYNAMIC WORKFLOWS

This is the biggest feature in the Opus 4.8. release - and the one you need to scope carefully or it'll eat your tokens alive.

Claude Code now writes a JavaScript orchestration script for your task and runs it in the background. The beauty of it is that the plan lives in code instead of the model's context, so only the final answer comes back to your session, and your terminal stays responsive while all the heavy work happens in the background.

The numbers:
```json
Up to 16 subagents running concurrently
Hard ceiling of 1,000 total per run
Resumable: if your laptop dies, it picks up where it stopped
Requires Claude Code v2.1.154+
```

Trigger it with /effort ultracode or just describe a big task:
```json
/effort ultracode
"Audit every endpoint under src/routes/ for missing auth checks"
```

When it's worth it:
- migrations across 200+ files
- full-codebase security audits
- project-wide test generation
- large refactors
- research across multiple repos

When it's overkill:
- simple bug fixes
- single-file edits
- quick questions

The official way to keep spend in check: scope the task, run the audit on one folder first, see how many subagents it spawns, then calibrate the big run from there.
```json
# test first
"audit src/routes/auth/ for missing checks"

# then scale once you know the cost
"audit all of src/ for missing checks"
```

To disable workflows entirely:
```json
CLAUDE_CODE_DISABLE_WORKFLOWS=1
```

Availability: on by default for Max, Team, and Enterprise. On Pro, turn it on in /config (and switch to Opus 4.8 first).

# CLAUDE FOR CONTENT & MARKETING

## Content generation

The process looks like this:
```json
Dump messy thoughts + my take into a draft

→ feed it to Claude with my skill file
→ get a structured version back
→ manually rewrite the intro, cut the filler, add my voice back
→ post
```

The secret weapon is a skill file - a markdown file with my writing rules, tone, post formulas, and examples of what performs.

## Vibe coding in Cursor

Key hacks:
```json
- keep a CLAUDE.md / .cursorrules in every project
  so you never re-explain your stack
- use Low effort for boilerplate, High for logic
- one feature per chat — don't let context bloat
- compact or start fresh every 30-40 messages
- ask for a plan BEFORE code on big changes
  (saves you from undoing wrong approaches)
```

The biggest one: describe the outcome, not the steps.

# CONFIG

Environment variables — add to ~/.zshrc or ~/.bashrc:
```json
# set Opus 4.8 as default model
export ANTHROPIC_MODEL="claude-opus-4-8"

# persistent default effort level
export CLAUDE_CODE_EFFORT_LEVEL=high

# disable dynamic workflows entirely (optional)
# export CLAUDE_CODE_DISABLE_WORKFLOWS=1
```

Safe permissions (settings.json):
```json
{
  "permissions": {
    "allow": [
      "Read", "Edit", "Write",
      "Bash(npm test)",
      "Bash(npm run *)",
      "Bash(git add *)",
      "Bash(git commit *)"
    ],
    "deny": [
      "Read(.env)",
      "Read(**/*.pem)",
      "Read(~/.ssh/**)",
      "Bash(rm -rf *)",
      "Bash(sudo *)",
      "Bash(git push *)"
    ]
  }
}
```

With this, the agent operates freely inside your project but physically can't: read secrets (.env / SSH keys / certs), nuke files (rm -rf), run sudo, or push to remote without your say-so.

## 研究摘要

**TL;DR**：Opus 4.8 token 快速消耗的根因是配置問題，文章提供 effort 5 層分級路由、fast mode 使用時機、dynamic workflows 範疇控制、daily cheat sheet 與 config 設定的完整指南。

### 核心論點

1. **Token 消耗根因三誤**：① 簡單問題用 High effort ② 全部設 Max「安全感」③ 從不 compact（第 40 條訊息時每輪重讀數千 token 歷史）
2. **Effort 5 層路由**：Low(~0.1x) / Medium(~0.4x) / High(1x, default) / xhigh(~2-3x) / Max(~4-8x)；核心：按任務類型路由，不要固定一個 level
3. **Fast Mode**：2.5x 速度，$10/$50 per 1M（原 $30/$150，降 3x）；適合 bulk 生成（refactor/docs/tests），不適合 debug/architecture/security
4. **Dynamic Workflows**：最多 16 subagents 並發，1,000/run ceiling，需先在子目錄測試規模再全量；Pro 需 /config 開啟
5. **一次配置永久生效**：env variables（ANTHROPIC_MODEL + CLAUDE_CODE_EFFORT_LEVEL）+ settings.json permissions（allow read/edit/write/test，deny .env/SSH/rm-rf/sudo/push）

### 關鍵數據 / 工具

- Effort 成本：Low ~$0.005 / High ~$0.05 / Max ~$0.20-0.40 per request
- Fast mode 定價：$10/$50 per 1M（2.5x 速度，原 $30/$150）
- Dynamic Workflows：16 並發 / 1,000 total ceiling，需 Claude Code v2.1.154+
- 指令：`/effort low/medium/high/xhigh/max/auto`、`/fast`、`/effort ultracode`、`/compact`
- 環境變數：`ANTHROPIC_MODEL`、`CLAUDE_CODE_EFFORT_LEVEL`、`CLAUDE_CODE_DISABLE_WORKFLOWS`

### 批判性觀察

1. Effort 分級路由是高實用性技巧，但每次手動判斷 effort level 有認知負擔，`/effort auto` 才是真正的懶人解法
2. Content & Marketing 部分明顯是作者個人推廣（病毒式推文工作流 + KOL 管理），與核心技術主題偏離，拉低整體一致性
3. 文章號稱 "workflows consume meaningfully more tokens" 但未提供具體倍數，`CLAUDE_CODE_DISABLE_WORKFLOWS=1` 是重要的保險但位置較隱沒
