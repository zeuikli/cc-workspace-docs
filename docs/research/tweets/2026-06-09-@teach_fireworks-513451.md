## 全文（摘要版）

這兩天海外 AI 圈圍著一句話吵得很熱：
> "You shouldn't be prompting coding agents anymore. You should be designing loops that prompt your agents."

換成工程語言，Agent Loop 不是一個概念包裝，它是 runtime。

一個普通 chatbot 接到問題，生成一次回答，然後結束。一個 agent 接到目標，會進入循環：讀取當前狀態，決定下一步，調用工具，觀察結果，把觀察重新寫回上下文，再決定是否繼續。

TinyAgents 把它壓到 5 行偽代碼：調用 LLM，檢查 tool calls，執行工具，把工具結果塞回 messages，再進入下一輪。

## 1. Agent Loop 的第一層價值：让模型从"回答"进入"推进"

Agent 多了一個動作面。把「我不知道」變成一次搜索、一次 API 調用、一次文件讀取、一次代碼執行。

上下文不再只是 prompt，它變成每一輪 action 後的狀態容器。工具不再只是插件，它變成 agent 觸碰世界的執行邊界。observation 不再是日志，它變成下一輪決策的輸入。

## 2. 第二层价值：loop 暴露了 agent 的真实失败点

加了 loop 以後，問題沒有消失，只是暴露得更清楚。常見失敗：循環不知道什麼時候停、工具返回壞結果、上下文越滾越亂、重複調用同一工具、目標已經偏了還在繼續。

一個 agent 能跑起來，只需要一個 while loop。一個 agent 能穩定交付，需要：max iterations / stop condition / tool schema / observation format / trace log / evaluator / budget guard。

循環不是免費的智能，它是帶帳單的控制系統。

## 3. 第三层价值：长任务 agent 的难点不是"跑久"，是"别漂"

大任務能收在有用狀態，通常不是因為模型強了 9.8 倍，而是目標周圍的結構更好。

長任務 agent 的失敗很穩定：context 被稀釋 / 一個錯誤變成整輪重啟 / 早期學到的東西消失 / verification 太晚才發生 / 人一直在旁邊 babysit / 最後停在「mostly done forever」。

真正決定 agent 能不能獨立幹活的，往往是 checkpoint 和 verify。沒有這兩層，loop 只會把不確定性跑得更遠。

## 4. 第四层价值：Autoloop 需要"判断变好"的机制

會重複的 loop 不等於會改進的 loop。壞流程重複一千次，只會更快地產生一千次壞結果。evaluator 是讓 loop 有意義的關鍵。
