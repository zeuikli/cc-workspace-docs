## 分析摘要

**TL;DR**：Fable/Mythos 首批實測報告；最驚人：Fable 自行發現代碼重複主動合併（負 diff）、用 Python 腳本一次解決整個 codebase 遷移——作者稱「Big model smell 有史以來最強」。

### 核心論點

1. **Big Model Smell 定義**：模型選擇「聰明版本」而非「顯而易見版本」路徑的直覺感受；作者人生只感受過 4 次（o1 / GPT-5.5 / Opus 4.5 / Fable），Fable 最強
2. **腳本化遷移（最可行動洞察）**：Zod 3→4 遷移，Fable 輸出單一 Python 腳本一次性處理整個 codebase；Codex 是逐檔修改——「write a script to do this」將成為 migration 新範式
3. **Agent 大作業**：50 份歷史計劃文件清理，294 sub-agents、15M tokens、一次 pass + 驗證搞定（Opus 4.5 同任務需 5–6 pass）
4. **自主去重（獨特觀察）**：開發途中 Fable 主動發現 3 處重複的 agent-driver 實作並提議合整；CLAUDE.md anti-duplication 規則被真正執行——作者「從未在任何模型看過」此行為；結果是負 diff
5. **侷限仍在**：「它還是 Claude 模型」——over-explain、stray scaffolding、random flourish 依然存在；smell 是更銳利，不是更自主

### 關鍵數據

- 294 sub-agents，15M tokens，1 real pass + confirm（vs Opus 4.5 的 5–6 pass）
- 負 diff（AI coding 中極罕見，通常模型只增加代碼）

### 批判性觀察

1. "Big model smell" 是主觀評估；但腳本化遷移和自主去重是**可重現的客觀行為差異**
2. 15M tokens、294 subagents 成本未提；「一次通過」的成本效益需更多數據
3. 刻意不提 benchmarks，比較困難但更接近真實工程體驗

# Fable smells big

Sounds funny, but I had the chance to Mythos/Fable this week. I've been trying to describe how it feels without sounding like every other launch-day thread.

Overall, it has big model smell.

If you've been around these models long enough you know the smell I mean. It's the feeling you get a few minutes into real work, where the thing on the other end is genuinely surprising. It reasons about the problem and finding a path you wouldn't have.

I've felt it maybe three times. o1 when it first dropped. GPT-5.5 over the past few months. Opus 4.5. That's basically the list.

Fable has the most of it I've felt yet.

## What big model smell actually is

Hard to define but I'll try. The model is heavy and you can feel the weight, but it doesn't waste it. It thinks for a while and then does the smart version of the task instead of the obvious one. That's pretty much it.

## Scripts scripts scripts

I had a codebase where I wanted to bump Zod 3 to Zod 4.

I'd already run this through Codex so I knew the shape of the expected answer. Codex scanned the repo, did some research on what changed in Zod 4, then went file by file updating each one.

Then with Fable, I thought it failed at first.

It researched. Then it kept researching. It spent so long that I had my finger on the escape button.

But what it output was a single Python script that programmitcally updated the whole codebase. It understood the problem well enough to write the tool that solved it, then used the tool.

Saved a pile of tokens and more importantly it was just correct. Been thinking about this one a lot. I expect "write a script to do this" is going to become the move for these newer models.

## High level planning

You know the usual rhythm with these things. Model builds a big plan, plan looks great, you start executing and reality sets in. Step four contradicts step seven. The approach you picked at thirty thousand feet doesn't survive the actual code and now you're spending the whole build tweaking the plan you just made.

Fable does this way less.

I built out a couple POC platforms with it and the plans mostly just held. It kept the contradictions and the little details in its head instead of dropping them the second it started writing code. At some point I realized I'd been typing "okay, next step" for like an hour straight.

Boring to write out but this is where all my time goes. The gap between a plan that looks good and a plan that executes is the whole game and this closed a lot of it.

## Agents agents agents

I have a repo with around fifty historical plans and another ten or so coming. They drift. An old plan gets superseded, an approach gets abandoned, and nobody (me) ever goes back and updates the doc. So any model reading them later inherits a pile of stale context and gets confused. I wanted the whole repo made pristine. Every old plan annotated with what's out of date, what got phased out by a later plan, where we actually went a different direction than written.

Pointed Fable at it as a workflow and let it run.

15 million tokens, 294 subagents. Found over a hundred separate spots that needed edits and made all of them.

Then I did the obvious thing and ran the whole workflow again to see what it missed. Two or three more items. That was it.

I'd run a version of this through Opus before. Took five or six passes to grind the count down to single digits. Fable got there in one real pass plus a confirmation run. I've been messing with orchestration since it shipped, mostly on Opus, and this is the first time it felt less like a party trick and more like something I'd hand a hundred-edit job to.

## Clean code

Okay this is the one that actually got me.

I was building an agent platform and I'd let three separate agent-driver implementations sprawl across the codebase. I have a line in my CLAUDE.md about hunting down duplication and collapsing it. Every model I've ever used treats that line as background noise. You have to physically point at the duplication before anything happens.

Fable brought it up on its own. Mid-feature it basically went, hey, this same code lives in three places, we should unify it.

I shipped that feature with a negative diff. If you've done any AI coding you know. These models add code, that's what they do. One deleting code on its own because it noticed the shape of the system was wrong? Never seen it.

## However...

I am not going to sit here and pretend the thing is perfect.

It's still a Claude model. I still had to hop in and say "remove that silly comment" more than once. Still does all the small dumb stuff every model does, the over-explaining, the stray scaffolding, the random flourish nobody asked for. If you're expecting to walk away and come back to perfect work you'll be disappointed, same as always.

The smell isn't autonomy. It's that the thing you're steering is sharper than what you're used to.

## What I am changing because of it

Few things already shifting in how I work:

1. Migration-shaped work gets a script now, not hand edits. That's going in my global CLAUDE.md now that I've watched a model reach for it unprompted.

1. I am done cancelling runs the second a model starts thinking too long — the long research budgets keep paying off.

1. I'm putting real workflows in front of it. This model feels like it has mastered orchestration.

Most capable model I've used to date. Not by a little.

## Sniff sniff

Benchmarks will tell you one story. They always do. The thing I keep coming back to isn't a number though. It's that first-hour feeling, the one I've only had a handful of times, where the model does something smarter than I would have and I have to sit back for a second.

That feeling always shows up before the benchmarks catch up. Learning to notice it early might be the most useful instinct you can build right now.

I've felt big-model smell three times before now.

Fable / Mythos is the fourth, and it's the strongest yet.
