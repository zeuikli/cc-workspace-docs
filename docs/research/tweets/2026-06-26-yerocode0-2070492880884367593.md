## 核心摘要

> Anthropic 官方示範如何用「迭代式 Prompt Engineering」逐步精煉 Claude 提示詞，以車禍保險理賠表單分析為真實案例貫穿全程。

- 提示詞工程是**迭代式實驗科學**：從任務描述出發，逐版本測試並觀察 Claude 的輸出差異
- 結構化提示詞的核心五要素：任務描述（Task Description）、逐步指令（Step-by-step Instructions）、背景文件（Background/Documents）、範例（Examples）、輸出格式控制（Output Format）
- **背景資訊內建**（Baking context in）：將表單結構說明直接放入 system prompt，可讓 Claude 輸出更準確、更簡潔，不需大量敘述
- **Few-shot 範例**的威力：提供真實難例（edge cases）後，Claude 的判斷置信度和一致性顯著提升
- Claude 4 / 3.7 的 **Extended Thinking**（延伸思考模式）可作為提示詞品質不足時的補救手段，並透過 `<thinking>` 標籤暴露推理過程供除錯

## 整理版（可讀逐字稿）

### 課程背景與應用場景（00:00–03:44）

本課程由 Anthropic applied AI 團隊成員示範，以「瑞典車禍保險理賠表單自動分析」作為貫穿案例。場景是：理賠系統接收到一張手繪事故草圖和一份有 17 個 checkbox 的標準表單，要求 Claude 判斷肇事方。

第一版 prompt 僅給最基本指示，Claude 的輸出存在問題：誤判為滑雪事故（非車禍），顯示在沒有足夠背景資訊時 Claude 會自行補充假設。這引出課程核心論點——**提示詞工程是迭代的實驗科學**，每個版本需要設立可驗證的成功條件。

### 五大最佳實踐（03:44–08:23）

講者整理 Anthropic 內部及對外推薦的 prompt 最佳實踐：

1. **任務描述（Task Description）**：開門見山告訴 Claude「你是誰、你在做什麼」，建立明確角色定位
2. **逐步指令（Step-by-step Instructions）**：像清單一樣列出推理步驟，引導 Claude 的思考路徑
3. **背景資料（Background/Data/Documents）**：把系統能提前知道的資訊（如表單結構、業務規則）事先嵌入
4. **範例（Examples）**：提供 few-shot 示範，尤其是邊界難例
5. **輸出格式（Output Format）**：明確指定回覆格式，包括 XML tag、JSON 結構，或使用 pre-fill 技術

第二版加入 AI Assistant 角色描述（在 Swedish 保險環境下工作），Claude 立即能正確辨識這是車禍而非滑雪事故，並準確讀出 checkbox 1（Vehicle A）和 checkbox 12（Vehicle B）的勾選狀態。

### 背景資訊內建的效果（08:23–12:41）

第三版將表單 17 個 checkbox 的含義全部內建到 system prompt（說明每一行代表什麼情境、兩欄分別對應哪輛車）。效果顯著：Claude 不再花時間「敘述表單結構」，而是直接分析並給出明確結論——Vehicle B 為肇事方，並列出具體依據。

**靜態背景知識應當預先嵌入，而非每次透過 user prompt 重新提供。**

### Few-shot 範例與對話歷史（12:41–15:42）

當案例存在灰色地帶時（如 checkbox 資訊不完整），few-shot 範例可提供 Claude 決策錨點。講者示範用 XML tag 包裹範例案例（`<example>`）。對於需要長期追蹤的用戶交互場景，**對話歷史（conversation history）**也應當納入 system prompt 作為上下文豐富化手段。

### 明確輸出格式與 Pre-fill（15:42–23:11）

要讓 Claude 輸出可被下游系統解析的結構，可透過兩種方式：

- **Output format 指定**：在 system prompt 中說明回覆必須包含 `<final_verdict>` XML tag 包裹最終結論
- **Pre-fill 技術**：在 assistant turn 預先填入開頭（如 `<final_verdict>`），強迫 Claude 從此格式起始，略過不需要的前言

### Extended Thinking 作為補充工具（23:11–24:10）

Claude 3.7 和 Claude 4 提供的 Extended Thinking 可彌補提示詞不夠精細的缺口。透過 `<thinking>` 標籤，開發者可觀察 Claude 的推理過程以進一步優化 prompt。建議：優先用明確提示詞引導，把 Extended Thinking 當作除錯工具或高難度任務的輔助，而非常規依賴。
