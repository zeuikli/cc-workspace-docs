## 核心摘要

> 講者（Thariq，Anthropic Claude Code 團隊）：瓶頸不在模型，在人——模型能做的事遠多於我們讓它做的事，而擋住我們的是自己的 unknown unknowns。

### 1. AI 還沒兌現自己的估值

軟體與知識工作正在變便宜，但創造價值本身沒有變簡單，兩者不是同一件事。他引 Anthropic 的內部價值觀「不跟自己談判」：與其自己先把優先序互相打折，不如全都要，讓現實告訴你真正的取捨在哪——因為在 AI 上，「好、快、便宜」是否還是三選二已經不確定。

### 2. 模型是長出來的，能力以尖刺方式浮現

資料、RL 環境與各階段訓練都是細心培育，但拿到模型前不知道它會擅長什麼。經典反例：在 Sonnet 3.5 時代若預測模型怎麼學會寫程式，直覺是 context window 擴到一億 token 把整個 codebase 塞進去；實際路徑卻是 tool calling + bash + grep。這種事前推導不出來，只能實測。

### 3. Capability overhang：Pokémon 案例

「哪些寶可夢名字以 -aw 結尾？」一千多隻裡剛好兩隻（Croconaw／Drednaw），純靠權重回憶或上網搜都答不好；丟給任何有 code exec 的 agent，它抓全表 grep 一行解掉，再往前一步能生一個支援任意 regex 查詢的 web app。差別不在模型智力，在使用者有沒有「幫它解開手銬」的技能——一般使用者問一次沒得到答案就停在那裡。

### 4. Human–Agent Interaction 是新技能

2010 年代的公司建立在 HCI 上，這一代要建立的是 HAI。跟 LLM 講話像寫作或公開演講，練得好的人產出差距極大，且會長期高槓桿。實作上要把自己放進 Claude 的處境：模型／harness／世界／你是四方關係。以 "explain how the auth module works" 為例，Claude 需要知道你是誰（技術程度、熟不熟這個 codebase）、世界多大（legacy 巨庫要花大量 compute 開 sub-agent，小庫直接讀完）、能否取得 git／Slack 旁證，以及**你為什麼問**——人被老闆這樣問會先反問「要拿來幹嘛」，Claude 拿不到這個 for-what。改良後的 prompt：「我是資深 TypeScript 工程師、對這模組零基礎、這題值得花 compute，請用 sub-agents。」

### 5. Claude Code 端到端剪影片，以及調色這個 unknown unknown

他的影片現在由 Claude Code 端到端剪：素材資料夾 + 他要講的稿子丟進去，Claude 轉錄所有片段、挑出與稿子最匹配的 cut、剪接、依團隊 Figma design system 生成 React overlay 編譯成片。他的定性：**知識工作正在變成一個由 agent 操控的、裝著 code / script / data 的資料夾**。

第一版與第二版的差距在調色。他懂 ffmpeg、懂轉錄、懂 Remotion（known knowns 讓他走到能剪片），但調色是純粹的 unknown unknown。修法不是換 prompt 而是把未知磨掉：請 Claude 解釋調色，第一份報告看完仍不懂（他稱這種「看起來很酷、其實沒學到」的現象為 education porn，多數人到這步就滑過去），於是持續追問「vector scope 是什麼」、要求引外部文獻、要求生成前後對照，最後讓 Claude 做出可逐像素觀察數值變化的視覺化。到這步他建立起心智模型（調色≈shader：吃一個像素、吐另一個像素），並拿到具體洞見：**膚色要與背景分開調，因為人眼對膚色的容錯範圍窄**（背景偏紫可以，臉偏紫不行）——而他這支片的膚色與背景色恰好很接近。

留給聽眾的一句話：**你很可能有一大堆 unknown unknowns，也因此不夠有野心。**

### 6. Q&A 重點

- **Claude Tag vs Claude Code**：探索、思考、生 artifact 用手機看 → Claude Tag；in-the-loop coding 仍在 Claude Code。Claude Tag 強在起頭、管理任務、多人協作，內部預設 multiplayer。
- **能力怎麼長出來的**：`ask_user_question`（他自己做進 Claude Code 的工具）從 Opus 4 勉強能呼叫一次，演進到能串接、一次丟 30–40 題面試你、到現在能生 HTML 報告讓你在報告裡選答案。markdown → HTML 同理：markdown 起初是模型自我對齊的手段，後來是溝通媒介，現在得換成 HTML 才解鎖新能力。**格式要跟著能力換**，但怎麼事先知道要換——他直說沒有科學方法，「大概是兆元問題」。
- **agentic 開發是不是退回瀑布式**：他的實務是大量便宜原型先行（HTML mockup，不必真的實作），因為「我常常不知道自己要什麼」，而這個發現往往埋在實作的 80% 處——正是最拖慢速度的地方。循環是 spec → interview → prototype →（有時 prototype PR）→ 看喜不喜歡 → **帶著學到的東西 reset 重來**。
- **還用 plan mode 嗎**：不用了。
- **怎麼決定該跟 Claude 學什麼**：沒有簡單答案。agentic engineering 很好玩，容易變成沒在推動任何成果的娛樂；該定期回頭問「我的產出哪裡不對」，答案通常是某個你講不清楚的 unknown unknown。不必什麼都學，但有些東西你非學不可。
