## 全文（核心技術段落）

**定位**：Fable = senior engineer，規劃/決策/調試硬問題/審查；**絕不**做 grep、boilerplate、browser automation 的 volume work。

### Phase 1 — Assessment Prompt
```markdown
Inspect my current setup and report where I stand on each recommendation:
- Read ~/.claude/settings.json: note my model, effortLevel, globally enabled plugins.
- Read ~/.claude/CLAUDE.md: do I have model-routing or subagent delegation rules?
- Check ~/.claude/agents/: any agent definitions with pinned models?
- Check for external code CLI (e.g. codex on PATH) or skills wrapping one.
Present as short table: recommendation / current state / already done/partial/not done.
```

### 7 具體建議

**1. 在 CLAUDE.md 增加 model-routing 段落**
```markdown
## Model & Token Routing

Fable (main loop) is for: architecture, planning, hard debugging, final
review/synthesis, and anything ambiguous. Everything else gets delegated
to cheaper models.

When spawning subagents (Agent tool) or workflow agents, set the model explicitly:
- **sonnet** (default for all exploration and analysis): file/code search,
  exploration fan-outs, codebase analysis, log scanning, data extraction,
  standard implementation from a clear spec, QA runs, doc updates.
  ⚠️ Do NOT use haiku for exploration — a subtly wrong exploration summary
  taken as given by Fable costs more than the tokens saved.
- **opus**: complex implementation, code review passes, tricky refactors
- **omit model (inherit Fable)**: only for design decisions, adversarial
  verification of critical findings, or synthesis across many agent results

Effort: use "low" for mechanical stages, session default for normal work,
"high"+ only for verify/judge/design stages.

Subagents must return conclusions with file:line references — never raw file
contents or dumps.
```

**2. 不要默認跑 1M context 變體**
`claude-fable-5[1m]` → 改回 `claude-fable-5`（除非日常需要整 codebase 在一個 session）。每次 turn 重讀累積上下文，1M 讓 session 累積遠多於必要。

**3. 重型 plugin 按 project 啟用，不全局**
每個 project 的 `.claude/settings.json` 啟用，而非 `~/.claude/settings.json`。每個 enabled plugin 的 skill/agent 描述每次 session 開始都載入上下文，對不使用的 session 是純 overhead。

**4. 探索任務強制用 model override**
在 `~/.claude/agents/` 建 `explorer.md`（前端設 `model: sonnet`），不依賴 orchestrator 記住。

**5. Subagent 返回 evidence（file:line）而非 dump**
節省兩次：(1) Fable 不用重讀便宜模型已讀的內容；(2) 讓探索可 spot-check，Fable 只需讀 5 行驗證。

**6. 大型實作委派給外部 CLI（Codex）**
Fable 寫緊湊 spec → 外部 CLI 執行 → Fable review diff。保留判斷兩端，省掉 volume 中段。

**7. 分層 effort，不要全 max**
中等 session 默認（medium/high），最難的 verify/judge/design 才用 xhigh（per-agent override），max 是單一難問題工具，不是吞吐量工具。

**Bonus**：Browser automation 用 headless-browser skill，不用 screenshot computer use（極度 token-heavy）。

## 研究摘要

**TL;DR**：7 條具體 Claude setup 優化建議，核心是把 Fable 定位為高判斷力的 orchestrator/reviewer，exploration/implementation volume work 全交給便宜模型；關鍵洞察：Haiku 做 exploration 的「靜默錯誤」成本比省下的 token 更貴。

### 核心論點

- **⚠️ 勿用 Haiku 做 exploration**：細微錯誤的 exploration summary 被 Fable 當真後放大，成本遠超省下的 token
- `claude-fable-5[1m]` 不是默認最優（session 累積上下文代價）
- Plugin 只按 project 啟用（每個 plugin 的 skill 描述都是 context overhead）
- Fork subagents 永遠繼承主循環模型（不受 model override 控制）
- Browser screenshot computer use 是最貴的 token 模態

### 關鍵數據 / 工具

- CLAUDE.md Model Routing 模板（含 sonnet/opus/Fable 分工）
- `~/.claude/agents/explorer.md`（pinned sonnet in frontmatter）
- `effortLevel` 分層：medium/high default；xhigh per-agent override
- `claude-fable-5` vs `claude-fable-5[1m]` 的成本差異

### 批判性觀察

- Haiku 禁 exploration 洞察是本文最值得加進 delegation-protocol 的發現
- 文章直接提供 CLAUDE.md 片段，可直接 copy-paste（高可行動性）
- 無定量成本數據，但機制解釋清晰
