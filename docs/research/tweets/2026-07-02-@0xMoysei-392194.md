## 全文摘要

**定位**：引用 Anthropic 官方 prompting guide，將 8 條核心規則整理為可直接套用的 CLAUDE.md 片段和 prompt 模板。

**定價背景**：Fable 5 = $10/M input, $50/M output, 1M context window, 128k output ceiling。

### 8 條核心規則

**Rule 1：給出 Why（意圖前置）**
```
I'm working on [larger task] for [who it's for].
They need [what the output enables].
With that in mind: [your actual request].
```

**Rule 2：設定明確否定（邊界塊）**
```
When I describe a problem or ask a question, the
deliverable is your assessment. Report what you
find and stop. Do not fix, send, edit, or delete
anything until I say go.
```
→ Fable 5 會主動採取未被要求的行動（起草未請求的 email、建立 git 備份分支）。每個指令都需要配對「不做什麼」。

**Rule 3：Effort Dial 對齊**
- low/medium → 常規任務
- high → Anthropic 推薦默認值
- xhigh → 能力敏感工作
- **關鍵洞察**：Fable 5 low effort 往往超過舊模型 xhigh 性能，成本遠低；不要在 changelog 摘要上跑 xhigh。

**Rule 4：停止過度規劃，讓它行動**

直接加入 CLAUDE.md 的一行：
> **"When you have enough information to act, act."**

替代「先研究所有東西再規劃」。深度研究用 Opus 4.8 → PRD → 再給 Fable 執行。

**Rule 5：要求它證明（驗證塊）**
```
Before reporting progress, audit each claim against
a tool result from this session. Only report work
you can point to evidence for. If something is not
verified, say so explicitly. If tests fail, say so
with the output. If a step was skipped, say that.
```
→ 在 Anthropic 測試中幾乎消除長 agentic run 的虛假狀態報告。**建議寫入 skills、agents 和 CLAUDE.md，而不是每次 paste。**

**Rule 6：⚠️ 不要要求原始推理（reasoning_extraction 詳解）**

- 分類器觸發三類：攻擊性網安技術 / 生物與生命科學 / **思考內容提取（extraction of the model's own thinking）**
- 系統 prompt 中的「explain your reasoning」固定語句 → 觸發 reasoning_extraction 拒絕
- **觸發後 reroute 到 Opus 4.8，rate 約 5% sessions**
- **⚠️ Reroute 後持續生效**：觸發語句留在 context 中 → 下一個 request 再次被 bounce；`/model fable` 可手動切回但語句不清除會再次觸發
- **修復**：審計 system prompt 和 CLAUDE.md，移除推理回顯指令，改用「summarized thinking display」設定

**Rule 7：先刪除再增加（減法原則）**

自我審計 prompt（直接使用）：
```
Reflect on my past Claude Code sessions to find the
highest-impact improvements to my setup. Cluster
findings across sessions. Per cluster, decide: new
skill, new automation, a fix, or nothing. Write the
candidates to a file. Diagnosis only, no changes.
```
→ 39 個 session 的一次跑出：需建的 skill、可自動化的 skill、CLAUDE.md 中誤導模型的過時行

**Rule 8：高槓桿目標（3 個類型）**
1. 大規模 Code Review：整個最大 repo，平行 reviewer，按嚴重度排重複發現
2. Clone 你付費的軟體：Opus 研究 → PRD → Fable 長期執行（案例：21,000 行 TypeScript / 90+ commits）
3. 重建工作流：跑 Rule 7 審計，讓 Fable 寫它自己推薦的 SKILL.md 和 automation

## 研究摘要

**TL;DR**：引用 Anthropic 官方文件的 8 條 Fable 5 規則，最關鍵是 reasoning_extraction 的「reroute 持續生效」機制、Rule 5 驗證塊（反虛假進度）和 Rule 7 自我審計 prompt。

### 核心論點

- **⚠️ reasoning_extraction reroute 持續生效**：觸發語句留在 context → 每次 request 都 bounce，必須清除 context 才能恢復
- **驗證塊應內建**：寫入 skills/agents/CLAUDE.md，不是每次 paste（10 次裡只記得 6 次的效率）
- **"When you have enough information to act, act"**：替換過度規劃的一行指令
- **Effort 反直覺**：Fable low 常超越舊模型 xhigh；高 effort 留給真正艱難的任務

### 關鍵數據 / 工具

- Fable 5 定價：$10/M input, $50/M output
- reasoning_extraction reroute rate：約 5% sessions
- Rule 5 驗證塊（Anthropic 測試：幾乎消除虛假進度報告）
- Rule 7 自我審計 prompt（session history → ranked batch list）

### 批判性觀察

- 「reroute 持續生效」是三篇文章（wquguru/0xMoysei/KSimback）中最具體的機制描述
- Rule 5 驗證塊 + 要求建入 CLAUDE.md 的建議直接對齊 workspace 的 unverified_success 閘門
- Rule 7 自我審計 prompt 是少見的「使用 Fable 改進 Fable 設定」的操作化方法
- 整體與 wquguru 高度重疊，但 reroute 持續性和自我審計 prompt 是增量
- 文章聲稱「6 Rules Straight From Anthropic's Docs」但實際有 8 條規則，標題和內容不一致
