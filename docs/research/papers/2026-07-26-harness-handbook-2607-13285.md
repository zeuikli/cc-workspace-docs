# Harness Handbook: Making Evolving Agent Harnesses Readable, Navigable, and Editable

## 摘要 / 核心貢獻

本文處理 agent harness 演化的核心瓶頸：**修改行為前，先找到該改哪裡**。現代 harness「大型、緊耦合、行為分散」（large, tightly coupled, behaviorally distributed），開發者與 coding agent 都難以把「想要的行為」映射到具體程式碼位置——這一步失敗，後續 edit plan 再好也落錯地方。

作者提出 **Harness Handbook**：由 harness codebase 經**靜態分析 + LLM 輔助結構化**自動合成的**行為中心表示**（behavior-centric representation），每條行為都連回實作它的原始碼位置。與傳統以「檔案／函式」組織實作知識的方式相反，Handbook 以「harness 做什麼」組織，讓人與 agent 先定位行為、再導航到程式碼。

配套機制 **Behavior-Guided Progressive Disclosure (BGPD)**：引導 agent 從高層行為描述逐級下降到相關實作細節，並**把候選位置對照當前原始碼驗證**（不是靠記憶或猜測）。

### Handbook 結構

- **三層文件樹（D）**：L1 系統總覽（lifecycle + 主要 stage）→ L2 各執行 stage 的元件總覽 → L3 source-backed 單元細節（依模式為 function 或 file）。
- **State-Register View（Z）**：記錄跨 stage 邊界的狀態關係。
- 底層構件：program graph（resolved call edges）、stage skeleton、cross-stage state register、對 repo 驗證過的 source locator。
- **兩種 leaf 模式**：function-as-leaf（自 seed skeleton 由上而下）／file-as-leaf（由下而上推論）——依 codebase 規模擇一。

### 評測設定

兩個開源 harness，各 30 條 behavior-driven modification requests（相同行為意圖）：

| Harness | 語言/型態 | 規模 | Handbook 模式 |
|---|---|---|---|
| Terminus-2 | Python terminal agent | 6 源檔／103 內部函式／257 resolved call edges | function-as-leaf，20 stages、106 L3 entries |
| Codex | Rust coding agent monorepo | 2,267 源檔／34,363 內部函式／159,960 resolved call edges | file-as-leaf，140 stages、2,267 L3 entries |

### 量化結果

**Planning win rate（Handbook-Assisted vs Baseline）**
- Codex：28.3% → **38.3%**（+10.0 pt）
- Terminus-2：26.7% → **45.6%**（+18.9 pt）
- 跨 judge 一致性：Codex 每個 judge 皆 +10.0 pt；Terminus-2 +13.3~+26.7 pt

**Planner token 用量（每 request）**
- Codex：0.102M → 0.089M（**−12.7%**）
- Terminus-2：0.058M → 0.053M（**−8.6%**）
- 即「planning 品質上升」與「planner token 下降」同時達成，非以更多 context 換品質

**Behavior localization F1（對 Opus 4.8 reference）**
- Codex file-level：46.6% → 61.8%（+15.2）；symbol-level：38.3% → 57.1%（+18.8）
- Terminus-2 file-level：74.1% → 84.7%（+10.6）；symbol-level：64.8% → 77.1%（+12.3）
- 對 GPT-5.5 reference：Codex file-level 47.3% → 52.3%（+5.0）；Terminus-2 file-level 76.5% → 89.3%（+12.8）

**完全定位失敗率（Wrong）**
- Codex file-level：37.0% → 14.8%（**−22.2 pt**）
- Terminus-2 symbol-level：24.1% → 13.8%（−10.3 pt）

**分類別增益**：Query 修改 +16.3~+26.7 pt；Cross-file 能力 +16.3~+20.0 pt；**Search-Hostile（搜尋不友善）請求 +20.0~+33.3 pt**——增益最大處正是 grep/關鍵詞搜尋最無力處。分難度：easy +3.7~18.3、medium +13.3~26.7、hard +3.7~23.3。

## 與 workspace 的關聯

- 本 workspace 的 `.claude/` harness（rules/skills/agents/hooks）正是論文所謂「evolving harness」：多次 Routine 提到「改行為時不確定該改 core.md 還是 refs/ 還是 skill」——即論文定義的 behavior localization 問題。
- L1/L2/L3 三層 + progressive disclosure 與 `context-management.md` §Progressive Disclosure「三層下沉落點」構念同源，本論文提供外部量化佐證（token 降 8.6~12.7% 同時品質升 10~18.9 pt）。
- **最強遷移點**：Search-Hostile 類別增益最大（+20~33 pt）——對應 workspace 中「語義存在但無固定關鍵詞」的規則（如「不可逆操作等確認」散落 core.md/security-hygiene/hooks），grep 式導航最弱之處。
