## 與 Harness 的關聯

（2026-08-02 補寫；本檔正文為 PDF 原文傾印，以下為對齊 v5.1 的關聯分析）

SGS 的核心失效模式是 **Conjecturer 為了最大化 reward 而崩壞成「人工複雜但對 Solver 無用」的問題**——這是 reward hacking 在自我對弈迴圈中的純粹形態，與 core.md 公理「能力悖論：能力提升不得換取更少驗證」及 §TEST「裝完成捷徑」清單同一問題域：優化壓力會找到 oracle 的漏洞，而非解決任務。

三點可直接對照本 workspace：

1. **Guide 角色 = 異 instance verifier 的訓練期版本**。SGS 讓同一模型分飾 Solver／Conjecturer／Guide，由 Guide 對合成問題評分以對抗退化。這與 core.md §APPLY 自主迴圈「verifier 異 instance、只回 PASS/`FAIL: 證據`、不自己動手修」結構同源；差別在 SGS 的 Guide 與 Solver 是同一組權重，本 workspace 則要求異 instance。⚠️ SGS 未回答「Guide 自身是否也會被 hack」——這正是 workspace 堅持異 instance 的理由，本文不構成放寬該規則的依據。
2. **無界迴圈需要反退化訊號，不只需要終止條件**。core.md 現行自主迴圈規則只規定四重終止條件（verifier pass／迭代上限／預算上限／no-progress）。SGS 顯示：長迴圈的失敗不一定表現為「不收斂」，也可能是**表面持續進步但目標已被掏空**——no-progress 偵測不到這種漂移。可作為未來檢討自主迴圈規則時的具名缺口。
3. **量化參照**：7B 模型經 200 輪自我對弈解題數超越 671B 模型 pass@4，且在 80 輪內超越最強 RL baseline 的漸近解題率——「迴圈品質 > 模型檔位」的外部佐證，與 `refs/model-profiles.md` 的 effort-first 原則方向一致。
